1. 概述
1.1 背景
赛道罗盘是一个 AI 驱动的科技公司商机发现与赛道选择决策系统。产品设计文档已定义四层架构、七 Agent、八大功能模块。本文档在此基础上，给出可落地的技术架构、数据模型、接口规范、AI Agent 实现方案、部署运维方案。
1.2 技术目标
●支持多源异构数据采集与清洗，日处理千万级信号。
●支持知识图谱、向量检索、RAG 增强生成。
●支持七 Agent 并行分析与工作流编排。
●支持赛道评分卡可配置、可解释、可追溯。
●支持 SaaS 与私有化部署，满足数据合规。
●系统可用性 99.9%，页面响应 ≤ 2s，报告生成 ≤ 5min。
1.3 术语
术语	定义
Signal	原始信号数据，如政策、专利、融资、招聘、社媒
Opportunity	机会卡片，由信号聚合分析形成
Track	赛道，具备市场空间、竞争格局和技术门槛的行业方向
Capability Profile	公司能力画像
Scorecard	赛道评分卡
Agent	具备特定分析能力的 AI 智能体
RAG	检索增强生成
TRL/CRL	技术就绪水平 / 客户就绪水平

4. 核心模块技术设计
4.1 公司能力画像
流程：
1.用户填写表单或上传文档。
2.后端解析文档（PDF/Word），抽取技术、专利、人才等信息。
3.调用 Embedding 模型生成能力向量，存入 PostgreSQL。
4.同步更新 Neo4j 中的公司节点和关系。
5.返回能力雷达图和推荐赛道边界。
关键接口：

# 能力画像向量化
def build_capability_vector(profile: dict) -> list[float]:
    text = f"""
    技术栈: {profile['tech_stack']}
    专利: {profile['patents']}
    人才: {profile['talents']}
    资金: {profile['funding']}
    渠道: {profile['channels']}
    """
    return embed(text)

4.2 趋势雷达
流程：
1.Airflow 定时触发采集任务。
2.采集器抓取政策、论文、专利、融资、新闻。
3.Kafka 消息队列缓冲。
4.清洗服务去重、标准化。
5.NER 抽取技术、公司、赛道实体。
6.写入 PostgreSQL、Neo4j、Milvus。
7.趋势侦察 Agent 分析，生成趋势列表。
趋势评分算法：

def trend_score(signal_count, growth_rate, policy_support, capital_heat):
    return (
        0.3 * normalize(signal_count) +
        0.3 * normalize(growth_rate) +
        0.2 * policy_support +
        0.2 * normalize(capital_heat)
    )

4.3 机会图谱
流程：
1.从 Neo4j 查询赛道、公司、技术、专利、融资关系。
2.前端 Cytoscape.js 渲染图谱。
3.用户可下钻节点，查看详情。
4.空白点识别：基于图算法（如社区发现、中心性）找出稀疏区域。
空白点算法：
// 找出连接度低的赛道节点 MATCH (t:Track) OPTIONAL MATCH (t)-[r]-() WITH t, count(r) AS degree WHERE degree < 5 RETURN t.name, degree ORDER BY degree ASC; 4.4 需求探针
流程：
1.接入社媒、评论、招标、招聘数据。
2.文本清洗、分词、情感分析。
3.使用 BERT 聚类痛点（HDBSCAN）。
4.计算需求强度： 
○频率：痛点出现次数
○情感强度：负面情感占比
○付费意愿：评论中提及价格/预算
○紧迫度：时间关键词
5.生成访谈提纲、问卷、落地页测试方案。
需求强度公式：

def demand_score(freq, sentiment, willingness, urgency):
    return (
        0.3 * normalize(freq) +
        0.3 * sentiment +
        0.2 * willingness +
        0.2 * urgency
    )

5. AI Agent 技术设计
5.1 Agent 编排架构
采用 LangGraph 构建有向图工作流：

[趋势侦察] → [需求挖掘] → [市场测算] → [竞争情报] → [技术评估] → [决策综合] → [监控预警]
     ↑                                                                          ↓
     └────────────────────────── 反馈循环 ──────────────────────────────────────┘

每个 Agent 是一个节点，状态在图中传递。支持并行执行、条件分支、循环。
5.2 Agent 通用结构

class BaseAgent:
    def __init__(self, llm, retriever, tools):
        self.llm = llm
        self.retriever = retriever
        self.tools = tools

    async def run(self, state: dict) -> dict:
        # 1. 检索相关上下文
        context = await self.retriever.retrieve(state['query'])
        # 2. 构建 Prompt
        prompt = self.build_prompt(state, context)
        # 3. 调用 LLM
        response = await self.llm.ainvoke(prompt)
        # 4. 解析输出
        result = self.parse_response(response)
        # 5. 更新状态
        state.update(result)
        return state

5.3 各 Agent 详细设计
5.3.1 趋势侦察 Agent
●输入：政策、论文、专利、新闻信号。
●工具：search_policies, search_patents, search_news。
●Prompt 模板：

你是一个科技趋势分析师。基于以下信号，识别出未来 6-12 个月可能爆发的技术方向。
信号：{context}
输出 JSON：
{
  "trends": [
    {"name": "", "description": "", "confidence": 0.0-1.0, "evidence": [""]}
  ]
}

5.3.2 需求挖掘 Agent
●输入：社媒、评论、招标、招聘。
●工具：cluster_pain_points, sentiment_analysis。
●输出：痛点聚类、需求强度评分。
5.3.3 市场测算 Agent
●输入：行业数据、财报、融资。
●工具：tam_sam_som_calculator。
●方法：自下而上（客户数 × 客单价）+ 自上而下（行业规模 × 渗透率）。
5.3.4 竞争情报 Agent
●输入：竞品、专利、招聘。
●工具：competitor_discovery, patent_analysis。
●输出：竞争格局、大厂威胁评分。
5.3.5 技术评估 Agent
●输入：技术文档、专利。
●工具：trl_assessment, crl_assessment。
●输出：六维评分（TRL/CRL/BRL/IPRL/TMRL/FRL）。
5.3.6 决策综合 Agent
●输入：各 Agent 输出。
●工具：scorecard_calculator, report_generator。
●输出：综合评分、决策报告。
5.3.7 监控预警 Agent
●输入：信号更新。
●工具：rule_engine, anomaly_detection。
●输出：预警通知、复盘建议。
5.4 RAG 流程

Query → Embedding → Milvus 检索 → Top-K 文档 → Rerank → 
  → Prompt 组装 → LLM 生成 → 引用来源 → 输出

混合检索：向量检索 + 关键词检索（BM25），融合排序。
引用来源：每个结论附带 source_id，前端可下钻。
5.5 模型路由与成本控制
●简单任务：Qwen2.5-7B / GPT-3.5。
●复杂分析：GPT-4o / Claude 3.5。
●私有化：本地部署 Qwen2.5-72B。
●缓存：相同 Query 结果缓存 24 小时。

7. 非功能设计
7.1 性能
场景	目标	方案
页面响应	≤ 2s	CDN、缓存、SSR
报告生成	≤ 5min	异步任务、模板预编译
向量检索	≤ 100ms	Milvus 索引优化
图谱查询	≤ 500ms	Neo4j 索引、查询优化
数据采集	日处理 1000 万条	Kafka + 分布式爬虫
7.2 安全
●认证：JWT + OAuth2。
●授权：RBAC，租户隔离。
●数据加密：传输 TLS 1.3，存储 AES-256。
●审计：操作日志保留 180 天。
●合规：GDPR、个人信息保护法，支持数据本地化。
7.3 可扩展性
●插件式数据源：新增数据源只需实现 DataSource 接口。
●插件式 Agent：新增 Agent 只需实现 BaseAgent 并注册到 LangGraph。
●水平扩展：无状态服务可横向扩展，K8s HPA。
7.4 可观测性
●指标：Prometheus + Grafana。
●日志：Loki + ELK。
●链路：Jaeger + OpenTelemetry。
●告警：Alertmanager + 企业微信/邮件。
7.5 可用性
●SLA：99.9%。
●容灾：多可用区部署，数据备份。
●降级：LLM 不可用时返回缓存结果。

●Neo4j：每日快照。

●MinIO：版本控制 + 跨区域复制。

10. 风险与应对
风险	影响	应对
数据源不稳定	信号缺失	多源冗余，人工上传兜底
LLM 幻觉	错误结论	RAG + 引用来源，人工复核
模型成本高	运营成本	模型路由，缓存，私有化
数据合规	法律风险	本地化部署，脱敏
评分模型偏差	决策误导	定期校准，版本管理
高并发	性能下降	异步、缓存、水平扩展
