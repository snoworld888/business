1. 产品概述
1.1 一句话定位
赛道罗盘是一个 AI 驱动的科技公司商机发现与赛道选择决策系统，把“凭感觉选方向”变成“信号扫描 → 机会生成 → 需求验证 → 技术匹配 → 决策报告 → 持续监控”的可追溯流水线。
1.2 产品目标
●帮助科技公司系统化发现商机，减少对个人经验和运气的依赖。
●将 PESTEL、TAM/SAM/SOM、TRL/CRL、BXT、赛道评分卡等方法论固化为可操作工作流。
●结合公司自身技术、人才、资金、渠道等能力，推荐可落地、可验证的赛道。
●输出带证据链的决策报告，并持续监控关键信号，触发复盘。
1.3 价值主张
对象	价值
创始人/CEO	更快找到技术能力、市场需求、商业模式的交集
战略部/创新部	从分散信息中系统化筛选赛道，形成可汇报的决策依据
产品负责人	量化验证需求强度、竞争壁垒和技术成熟度
投资部	从集团能力出发筛选协同赛道，而非通用投资分析
专家/顾问	人机协同，专家校准沉淀为评分模型，越用越准
1.4 非目标
●不做通用资讯聚合平台。
●不替代投资尽调、法律尽调、财务尽调。
●不提供自动交易或自动投资决策。
●不承诺预测未来，只提供可追溯的决策辅助。

2. 背景与问题
2.1 市场背景
科技公司面临技术迭代快、政策变化多、竞争格局动态调整的环境。AI、量子计算、脑机接口、6G、具身智能、商业航天等前沿技术不断涌现，但“技术能做”不等于“市场该做”。赛道选择错误会导致资源浪费、窗口期错失。
2.2 用户痛点
●信息分散在政策文件、专利、融资事件、招聘 JD、招标信息、社媒评论、财报中，难以系统整合。
●缺乏量化工具，赛道评估依赖直觉和少数专家经验。
●需求验证周期长，客户付费意愿难以提前判断。
●竞争情报不完整，容易低估大厂威胁或高估自身壁垒。
●决策依据不可追溯，事后复盘困难。
2.3 现有方案不足
现有方案	不足
行业报告	静态、通用，难以匹配公司自身能力
资讯平台	信息过载，缺少决策工作流
投资数据库	偏财务和融资，缺少技术与需求验证
专家咨询	成本高、周期长、难以持续监控
内部战略会	依赖个人经验，缺少证据链和动态更新

4. 核心概念与术语
术语	定义
赛道	具备一定市场空间、竞争格局和技术门槛的行业方向
信号	政策、技术、融资、招聘、招标、社媒等原始数据
机会	由信号聚合分析后形成的潜在赛道或产品方向
能力画像	公司技术、人才、资金、渠道、供应链等能力的结构化描述
需求强度	用户痛点频率、付费意愿、紧迫程度的综合评分
技术成熟度	基于 TRL、CRL、BRL、IPRL、TMRL、FRL 的六维评估
赛道评分卡	可配置权重的多维评分模型
验证实验	针对关键假设设计的落地页、访谈、POC、预售等测试
变相时刻	行业格局、技术或政策发生重大变化的时点
证据链	每个结论可下钻到原始数据和推理过程

5. 产品目标与成功指标
5.1 北极星指标
被采纳的赛道决策报告数量 / 月。
5.2 关键指标
指标	说明	目标
机会发现数量	每月生成候选机会数	≥ 50
验证周期缩短比例	相比传统调研	≥ 40%
报告采纳率	被用于立项或投资决策	≥ 30%
付费转化率	免费到专业版	≥ 8%
预警准确率	关键信号触发有效复盘	≥ 70%
用户留存	专业版月留存	≥ 85%
5.3 验收标准
●用户可在 30 分钟内完成公司能力画像。
●系统可在 24 小时内生成首批候选赛道。
●每个赛道评分可下钻到至少 3 类证据来源。
●报告可导出 PPT/Word/Notion。
●关键信号变化可触发站内/邮件预警。

6. 总体架构
6.1 四层架构
层级	功能	关键组件
信号层	数据采集	API、爬虫、人工上传、第三方数据源
认知层	AI 分析	知识图谱、向量库、RAG、评分模型
决策层	工作流	能力画像、机会图谱、赛道评分、验证实验、报告
行动层	监控与复盘	信号预警、假设看板、实验追踪、复盘库
6.2 七 Agent
Agent	职责
趋势侦察 Agent	每日扫描 PESTEL、技术拐点、政策红利
需求挖掘 Agent	聚类社媒/评论/招标/招聘中的痛点，输出需求强度
市场测算 Agent	自下而上+自上而下测算 TAM/SAM/SOM
竞争情报 Agent	竞品动态、大厂威胁、替代方案、供应链卡点
技术评估 Agent	TRL/CRL/BRL/IPRL/TMRL/FRL 六维评分
决策综合 Agent	综合评分，生成立项/投资报告
监控预警 Agent	跟踪关键信号，触发“变相时刻”提醒
6.3 数据流
1.信号层采集原始数据。
2.认知层清洗、抽取实体、构建知识图谱、生成向量。
3.七 Agent 并行分析，输出中间结论。
4.决策层汇总评分，生成机会卡片和报告。
5.行动层持续监控，更新评分和预警。
6.4 技术栈建议
●前端：React / Next.js + ECharts / D3.js。
●后端：Python FastAPI / Node.js NestJS。
●AI：LLM + RAG + LangChain / LlamaIndex。
●知识图谱：Neo4j / NebulaGraph。
●向量库：Milvus / Qdrant / pgvector。
●数据管道：Airflow / Prefect。
●部署：私有化 Docker/K8s，支持 SaaS。

7. 功能需求
7.1 公司能力画像
功能描述：输入公司技术栈、专利、人才结构、资金、渠道、客户资源、供应链，生成能力向量和可进入赛道边界。
输入：表单、文档上传、API 接入。
输出：能力雷达图、能力标签、推荐赛道边界。
关键交互：
●支持模板导入。
●支持专家校准。
●能力变化时自动更新推荐。
验收标准：
●30 分钟内完成初始画像。
●能力标签可被赛道评分卡调用。
7.2 趋势雷达
功能描述：扫描 PESTEL 宏观环境、技术成熟度曲线、资本热度、政策文件，输出候选技术方向。
输入：政策网站、论文、专利、融资数据、新闻。
输出：趋势列表、顺风/逆风标注、技术成熟度位置。
关键交互：
●按行业、地域、时间筛选。
●点击趋势查看证据链。
●订阅趋势预警。
验收标准：
●覆盖至少 5 个数据源。
●每条趋势至少 3 条证据。
7.3 机会图谱
功能描述：可视化赛道节点、上下游、玩家、专利、融资、招聘热度，识别空白点。
输入：知识图谱、竞争情报、市场数据。
输出：赛道地图、竞争格局图、空白点列表。
关键交互：
●节点下钻。
●对比不同赛道。
●导出图谱。
验收标准：
●支持至少 100 个节点流畅交互。
●空白点可转为机会卡片。
7.4 需求探针
功能描述：接入社媒、评论、论坛、招标、招聘 JD，LLM 聚类痛点，输出需求强度、付费意愿、CRL。
输入：社媒 API、评论、招标、招聘数据。
输出：痛点聚类、需求强度评分、访谈提纲、问卷、落地页测试方案。
关键交互：
●关键词配置。
●情感与频率分析。
●一键生成验证实验。
验收标准：
●需求强度评分可解释。
●支持至少 3 种验证实验模板。
7.5 赛道评分卡
功能描述：可配置权重的多维评分模型，输出机会评分、雷达图、风险预警、排序列表。
默认维度：
维度	权重示例
市场空间	20%
需求真实性	20%
技术成熟度	15%
竞争壁垒	15%
商业模式	10%
时机	10%
内部匹配度	10%
输入：机会卡片、能力画像、Agent 分析结果。
输出：评分、雷达图、风险预警、排序。
关键交互：
●自定义权重。
●人工调整评分并记录理由。
●版本对比。
验收标准：
●评分可下钻到证据。
●权重调整实时更新排序。
7.6 验证实验管理
功能描述：管理假设 → 实验 → 指标 → 结论，支持落地页、预售、POC、客户访谈、渠道测试。
输入：假设、实验设计、指标。
输出：实验看板、结论、评分更新。
关键交互：
●实验模板。
●数据自动追踪。
●结论回写赛道评分。
验收标准：
●支持至少 5 种实验类型。
●实验数据可导出。
7.7 决策报告生成
功能描述：一键生成立项报告/投资备忘录，含证据链、假设清单、里程碑、风险。
输入：赛道评分、Agent 结论、实验数据。
输出：PPT/Word/Notion/PDF。
关键交互：
●模板选择。
●人工编辑。
●版本管理。
验收标准：
●报告含至少 5 个证据引用。
●导出格式兼容主流工具。
7.8 监控与复盘
功能描述：关键信号变化时预警，记录决策依据，事后复盘，校准评分模型。
输入：信号更新、决策记录、实验结论。
输出：预警通知、复盘报告、模型校准建议。
关键交互：
●预警订阅。
●复盘看板。
●评分模型版本管理。
验收标准：
●预警延迟 ≤ 24 小时。
●复盘记录可追溯。
7.9 系统管理与权限
功能描述：用户、角色、权限、数据源、模型配置、审计日志。
输入：管理员配置。
输出：权限矩阵、审计日志。
验收标准：
●支持 RBAC。
●操作日志保留 ≥ 180 天。

8. AI Agent 设计
Agent	输入	输出	依赖	关键指标
趋势侦察	政策、论文、专利、新闻	趋势列表、顺风/逆风	信号层	覆盖率、时效性

9. 数据设计
9.1 数据源
●政策：政府网站、产业政策文件。
●技术：论文、专利、技术社区。
●资本：融资事件、财报、招股书。
●人才：招聘 JD、人才流动。
●市场：招标、应用商店评论、社媒、论坛。
●供应链：企业公告、行业数据库。
9.2 核心实体
●公司、技术、产品、赛道、机会、信号、专利、融资、人才、客户、实验、报告、用户、角色。
9.3 知识图谱
实体关系：公司—拥有—技术；技术—应用于—赛道；赛道—包含—机会；机会—依赖—能力；信号—影响—赛道；实验—验证—假设。
9.4 向量库与 RAG
●文档切片、嵌入、存储。
●检索增强生成，引用来源。
●支持私有化部署。

13. MVP 范围与迭代路线
13.1 MVP 目标
验证“AI 能否帮科技公司更快筛出可验证赛道”。
13.2 MVP 功能范围
●聚焦垂直领域：AI+制造、AI+医疗、新能源科技。

总结：赛道罗盘的本质是科技公司的赛道决策操作系统。它把 PESTEL、TAM/SAM/SOM、TRL/CRL、BXT、赛道评分卡等方法论固化为工作流，用 AI Agent 完成信号扫描、需求验证、竞争分析和报告生成，最终帮科技公司找到“技术能力、市场需求、商业模式”的交集。
