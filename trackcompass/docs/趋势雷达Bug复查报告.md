## 三、新发现 ①：历史数据未回算（**这是"漏项"的真凶**）

### 现象

回算前 18/35 条趋势有匹配，而其中这几条明显应该有：

```
工业视觉与智能质检规模化落地      match=False   ← 但证据信号关键词含「计算机视觉」
工业视觉与智能质检的鲁棒性优化    match=False
轻量化边缘AI质检与快速部署方案    match=False
轻量化预测性维护时序模型         match=False
```

### 根因

`factors._capability` 是**落库时算好的快照**，代码修复后**不会自动重算**。时间线正好卡在修复点：

| 趋势 | 创建时间 | 落库 match | 证据里实际有 |
| --- | --- | --- | --- |
| 工业视觉与智能质检规模化落地 | 09-14 **08:55** | **False** ✗ | 计算机视觉 ✅ |
| 工业视觉与数字孪生规模化应用 | 09-14 **09:41** | True ✓ | 计算机视觉 ✅ |

> 09:41 正是当天修复 `_capability_pool` 的时刻。之后落库的用新逻辑（正确），之前落库的仍是旧结论。

### 修复

一次性回算：按**当前公司（磅旗科技）**画像重算比对池 → 更新 `factors._capability`，并打 `recalc: 2026-09-15` 标记。

**干跑先行（关键步骤）**：先只算不写，确认方向 —— `需更新 5 条 | 变多 5 条 | 变少 0 条` ⇒ **纯改善，无副作用**，才执行。

```
工业视觉与智能质检规模化落地        [] → ['计算机视觉']
工业视觉与智能质检的鲁棒性优化      [] → ['计算机视觉']
轻量化预测性维护时序模型           [] → ['计算机视觉']
轻量化边缘AI质检与快速部署方案      [] → ['计算机视觉']
智能质检                        None → ['计算机视觉']
```

**结果：18/35 → 23/35**，API 层立即可见（无需重启，读同一 SQLite）。

> ⚠️ 干跑时踩过一个坑：`db.query(CompanyProfile).first()` 拿到的是「智造未来科技」而非当前公司「磅旗科技」，
> 导致 `人形机器人…` 从 `['具身智能']` 变 `[]`（**变差**）。当前公司口径是 **`updated_at` 最近**，
> 不是 `first()`。若直接执行就会误伤 3 条正确标注。

## 四、新发现 ②：专利抽词产生碎片（污染画像面板）

### 现象

切换公司到「智造未来科技」时，能力词里出现无意义碎片：

```
能力词: ['计算机视觉', '深度学习', '边缘计算', '小样本工', '业缺陷识', '别模型训', '练方法']
                                              ↑ 全是碎片
```

### 根因

`base.py::extract_tech_keywords` 的兜底用**固定 4 字窗口**切分，完全不管词边界：

```python
for gram in re.findall(r"[\u4e00-\u9fff]{2,4}", text):   # 贪婪切 4 字
```

专利标题「面向小样本的工业缺陷识别模型训练方法」被切成
`小样本工` / `业缺陷识` / `别模型训` / `练方法` —— 每个都横跨两个词的边界，既匹配不到任何信号，又以「能力词」身份显示在面板里。

### 修复

移除该兜底 —— 调用方 `trend.capability_terms` 本就有 `or [text]` 兜底，返回空即可：

| 输入 | 修复前 | 修复后 |
| --- | --- | --- |
| 面向小样本的工业缺陷识别模型训练方法 | `['小样本工','业缺陷识','别模型训','练方法']` | `[]` ✅ |
| 一种基于深度学习的表面缺陷检测方法及系统 | `['深度学习']` | `['深度学习']` ✅ |
| 基于计算机视觉的智能质检装置 | `['计算机视觉','智能质检']` | `['计算机视觉','智能质检']` ✅ |

## 八、方法论沉淀

1. **"代码修好了" ≠ "线上好了"**：本次两个新问题都属于**修复不完整** ——
   一个是**数据侧未回算**（快照型字段），一个是**兜底逻辑残留**。
   修完代码后必须问一句：*这个字段是实时算的，还是落库快照？*
2. **数据回算必须先干跑**：本次干跑救回 3 条误伤（画像选错导致 `变少`）。
   干跑指标就一个 —— **`变少 = 0` 才允许写库**。
3. **当前公司口径是 `updated_at desc`**，不是 `first()`。凡涉及"以哪个公司为准"的逻辑都用 `get_profile()`。
