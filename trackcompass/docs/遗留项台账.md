## 一、P1 —— 多租户正确性（**上线前必须解决**）

> 本组为 2026-09-16「公共数据层」改造的**已知不完整**部分。
> ⚠️ 共同前提：**当前是单组织部署**（1 个演示租户 + 1 个 E2E 租户），
> 因此下列问题在单组织下**不产生实际数据泄露**，是**结构性欠债**而非在线缺陷。
> **触发条件统一为：接入第 2 个真实组织租户之前必须完成。**

### L-01 知识图谱仍为全局单例

| 项 | 内容 |
| --- | --- |
| 来源 | `docs/公共数据层与E2E租户隔离.md` §六-1 |
| 现状 | `MemoryGraphStore` 是**进程内全局单例**；`build_from_signals()` 已限制只纳入**公共信号**，但 `trends` / `opportunities` 节点仍是**全租户混合** ⇒ A 租户的趋势节点会出现在 B 租户的图谱视图与「中心性排名」「空白点」里 |
| 影响 | 跨租户**读**泄露（仅图谱可视化与图算法，不涉及写入） |
| 建议方案 | 把 store 改按租户分片（`dict[tenant_id, MemoryGraphStore]`），或拆「公共图谱 + 租户叠加层」 |
| 改动面 | `services/graph.py`（单例结构）、`analysis.py::refresh_graph`、`api/v1/graph` 与 `opportunities.py` 的调用点、`tests/test_services.py` |
| 触发条件 | 接入第 2 个真实组织租户**之前** |
| 状态 | ⬜ 暂缓（2026-09-16 用户决定） |

### L-02 私有信号的向量检索未隔离

| 项 | 内容 |
| --- | --- |
| 来源 | `docs/公共数据层与E2E租户隔离.md` §六-2 |
| 现状 | `analysis.py::reindex` **只索引公共信号**（`tenant_id IS NULL`）⇒ 租户自有的私有信号（`POST /signals` + `is_public=false`）**检索不到** |
| 影响 | 功能缺失（非泄露）。取的是「**宁可不检索也不泄露**」的保守解 |
| 建议方案 | 按租户分区索引：RAGFlow 每租户独立 dataset，或单 dataset + 命名空间过滤 |
| 触发条件 | 出现第一个「租户上传私有材料且需要被 RAG 召回」的真实需求时 |
| 状态 | ⬜ 暂缓（2026-09-16 用户决定） |
