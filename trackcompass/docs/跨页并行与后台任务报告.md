# 跨页并行与后台任务报告

> **触发**：用户 2026-09-16 ——「各个页面排查一下，这个系统应该是并行的，每个页面的操作，
> 切换页面应该可以得到结果，用户不可能在一个页面上一直等待」
> **结论**：9 个页面的 12 个手动操作全部改为**应用级后台任务**：切页不中断、跑完弹全局通知、
> 回到页面自动认领结果、顶栏实时显示「N 个任务后台运行中」。
> **改动面**：新增 `api/taskStore.ts` + 9 个页面 + 顶栏；零后端改动、零数据库改动、零新依赖。

---

## 一、问题：把「活干完了」和「用户看得到」接上

先说清一件事，否则会误判为「请求被取消了」：

- 服务端是**同步接口**，HTTP 请求**不会**因为前端组件卸载而中断 —— 活一定会干完（也照常落库）；
- 断点在**前端**：接结果的处理函数挂在页面组件上，**组件一卸载，响应就没人接**。
  于是出现「活干完了，用户却什么都没看到」。

所以本次要补的不是「让请求继续跑」（它本来就在跑），而是：

1. **有个地方接住结果**（不再依赖某个组件还活着）；
2. **跑完能通知到人**（哪怕人已经切到别的页面）；
3. **回到页面能把结果认领回来**，并能看出「它是按什么参数跑的」。

用户不需要判断「这个按钮会不会丢」，行为统一才不会踩坑。

## 三、设计

### 3.1 分层

```
frontend/src/api/taskStore.ts    应用级任务注册表（模块级 Map + 订阅 + 会话态镜像）
frontend/src/layout/AppLayout    顶栏「N 个任务后台运行中」指示器
各页面                            runTask() 发起 + useTask() 认领
```

### 3.2 关键决策

| 决策 | 理由 |
| --- | --- |
| **不取消请求**（不用 AbortController） | 服务端已经在干活了，掐断等于白干。任务的生命周期与页面解耦 |
| **同 key 不并发** | 「开始分析」连点两下不该跑两遍（尤其 47s 的七 Agent）。第二次点击直接忽略 |
| **共用 key 而非每页独立** | 趋势扫描在「工作台 / 趋势雷达 / 能力画像」三处、采集在「信号库 / 设置」两处是**同一件事** ⇒ 共享 `trends:scan` / `signals:collect`，既防并发，也能看到「别人发起的那次还在跑」 |
| **结果镜像到 sessionStorage** | 与其它会话态同生命周期；顺带支持「刷新页面后仍能看到上次结果」 |
| **残留 `running` 一律改判为「已中断」** | 刷新页面会把在飞请求杀掉。若还报「进行中」，顶栏会**永远转圈骗人** —— 宁可说「请重跑」 |
| **完成弹全局 `notification`** | 唯一能跨页面触达的方式（页面内的 toast 随组件一起消失） |
| **通知里不做「去查看」跳转** | 任务可能属于任意页面，强行导航会打断用户当前操作 |
| **结果认领走同一条路径** | 「本页完成」与「离开期间完成」共用同一个 effect，避免两条分支逻辑漂移 |
| **任务自带 `meta.params`** | 结果必须能自证「按什么条件跑出来的」（沿用会话态报告 §2.3 的同一条约定） |
| **任务完成即 `dataVersion+1`** | 列表页把它放进 `useAsync` 依赖 ⇒ **正开着该页时，别的页面发起的任务跑完，列表自动刷新** |

### 3.3 为什么不上 WebSocket / 任务队列

服务端目前就是同步接口，收到响应即完成，没有中间进度可推。上 WS 只是把「等 HTTP」换成「等消息」，
复杂度翻倍而体验不变；真要做异步队列（Celery + 轮询）时，**只需替换 `runTask` 内部实现**，
页面侧代码一行不用动 —— 这正是把这一层抽出来的价值。

## 四、逐页改动

| 页面 | 任务键 | 认领后的动作 |
| --- | --- | --- |
| 需求探针 | `demand:probe` | 写结果 + 条件快照；「清除结果」时连任务一起清（否则下次进来又被捞回来） |
| 赛道评分 | `scorecard:analyze:<机会 id>` | 按机会卡片存明细 + 本次分析依据；列表/评分卡随 `dataVersion` 刷新 |
| 趋势雷达 | `trends:scan` | 写扫描面板 + 扫描时间；趋势列表自动刷新 |
| 工作台 | `trends:scan`（共用） | 弹结果弹窗；弹过即清任务（不重复打扰）；按钮补 `loading` |
| 能力画像 | `trends:scan`（共用） | **不等待，立刻跳趋势雷达**；扫描在后台继续，列表自动补上 |
| 信号库 | `signals:collect` | 自动打开采集报告弹窗；关闭弹窗 = 已读 ⇒ 清任务（下次不再弹） |
| 设置 | `signals:collect` / `settings:reindex` | 刷新数据源统计与审计日志 |
| 决策报告 | `reports:generate` | 写预览面板；报告列表随 `dataVersion` 刷新 |
| 监控复盘 | `monitor:scan` | 刷新预警列表 + 校准预览 |

**未改造**（亚秒级、且切页不会丢结果）：验证实验的创建/回写/导出、图谱重建、能力画像保存
（保存本就会落库，且未保存内容已有草稿兜底）。

并行场景的实测链条（真实 Chromium + 真实大模型）：

```
① 需求探针回到空态（确保「结果是被认领回来的」，不是残留）
② 点「开始分析」→ **立刻**切到趋势雷达（不等结果）
   ✅ ★ 顶栏显示「1 个任务后台运行中」           ← 离开页面后活还在跑
   ✅ ★ 在趋势雷达页收到「需求分析完成」全局通知   ← 实测两次：8.1s / 1.0s（见下）
   ✅   任务状态已落会话态 status=done
        参数={"keywords":["并行冒烟wr19"],"sources":[8 类],"industry":"AI+制造"}
③ 切回需求探针
   ✅ ★ 自动认领结果（页面直接显示「上次分析 …」，**没有**回到「尚未执行分析」）
```

截图留档：`docs/跨页并行-任务运行与通知-验证.png` —— 人在**趋势雷达**页，
右上角弹出「需求分析完成」全局通知（这是「平行」最直观的一张图）。

> ⚠️ **写测试要考虑 LLM 缓存**。用例里的关键词是随机串，本意是绕开缓存 ——
> 但**并不保证**：随机词命中 0 条信号时，prompt 可能与被缓存过的那次完全相同，
> 实测第二次运行只花了 1.0s（第一次 8.1s）。
> 因此**断言本身不依赖耗时**：顶栏那条用轮询（容忍快任务），
> 结果正确性一律看「任务状态 + 页面是否认领」，不看秒数。

**未做的增强**（明确记录，避免被当成漏项）：
- 任务**进度百分比**：服务端同步接口不提供中间进度，顶栏只能显示「运行中」。要做需后端异步队列。
- 任务**取消**：同上，取消需要后端支持（且七 Agent 中途取消会留下半成品数据，风险高于收益）。
- 任务**历史列表**：目前只保留最近状态（会话级）。需要「任务中心」页面时再做。
