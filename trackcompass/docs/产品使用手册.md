## 通用交互：任务在后台跑，不必守着页面

系统里所有「点一下、要等几秒到几十秒」的操作（趋势扫描、需求探针、七 Agent 分析、
信号采集、报告生成、索引重建……）都是**后台任务**：

| 现象 | 说明 |
| --- | --- |
| 点击后按钮进入 loading | 任务已提交，**但你不必留在这一页** |
| 顶栏出现 `N 个任务后台运行中` | 鼠标悬停可看是哪个页面、哪个任务 |
| 切到别的页面 | 任务**继续跑**，不会被中断 |
| 任务完成 | 右上角弹**全局通知**（带结果摘要），无论你当前在哪一页 |
| 回到发起页 | 结果**自动出现**，不需要重跑；页面顶部会标明「上次分析 时间（条件）」 |
| 列表页正开着 | 别的页面发起的任务跑完，列表也会**自动刷新** |

几点设计取舍，提前说明以免误解：

- **同一件事不会跑两遍**：趋势扫描在「工作台 / 趋势雷达 / 能力画像」三处是同一个任务；
  采集在「信号库 / 设置」是同一个任务 —— 一处已经在跑，另一处的按钮会同步显示进行中。
- **没有进度百分比**：后端是同步接口，不提供中间进度，只能显示「运行中」。
- **没有「取消」按钮**：中途取消会留下算了一半的数据，风险大于收益，因此不提供。
- **页面刷新会中断任务**：这时顶栏不会再显示「运行中」，请在页面上重新执行
  （系统的态度是**宁可让你知道要重跑，也不假装还在跑**）。
> 未保存的填写不会丢：离开页面再回来会恢复（见「能力画像」页说明）。

## 三、逐页操作说明

### P02 工作台

- **四个统计卡**：机会卡片数、待处理预警、进行中实验、已生成报告 —— 点击即跳转对应模块。
- **开始趋势扫描**：一键触发趋势侦察 Agent，完成后弹窗展示扫描结果并跳转趋势雷达。
- **机会与预警 Tab**：左侧是排序条形图 + 机会列表（分数、结论、证据数、风险数），右侧是预警通知与最新趋势。
- **分析引擎状态 Tab**：展示七 Agent 的四层编排图（哪些并行、哪些串行）与运行时健康检查 JSON。

### P03 能力画像

#### 多公司管理（切换主体）

页面顶部有 **「当前公司」** 选择器，用于在已保存的多家公司之间切换：

| 操作 | 效果 |
| --- | --- |
| 在「当前公司」下拉里**选一家已保存的公司** | 该公司画像全量回填到左侧表单与右侧雷达/赛道面板，可直接查看或修改 |
| 点 **新建公司** | 清空表单，进入新建态（标签显示「未保存（新建中）」）；保存后创建**新的**一份档案 |
| 选一家公司后改内容并保存 | **更新该公司**（不会新建，也不会覆盖其他公司） |
| 输入一个已存在的公司名并保存 | 视为**同一家公司**，执行更新，**不会重复建档** |

> **分析主体规则**：趋势分析、赛道评分、决策报告均以 **「当前公司」** 为主体。
> 「当前公司」= **最近保存的那一份**。所以「切换公司 → 保存」即等于切换分析主体。
> 只切换下拉、不做任何修改时，也会把该公司载入界面供查看（不改变其数据）。
>
> 顶部标签会显示 **已保存 · 时间**，可据此确认界面上的数据是否已落库。
> 若画像列表或某家公司加载失败，顶部会出现**红色错误条 + 重试按钮**（此前是静默的）。

> **离开页面再回来会恢复现场**（2026-09-16 起）：
> - **选中的公司保留** —— 不再回到「最近保存的那家」。你上次在看哪家，回来就还是哪家。
> - **未保存的填写保留** —— 表单里填了但没保存的内容会恢复，顶部同时给出黄色提示
>   「已恢复未保存的草稿（时间）」，并提供 **丢弃草稿** 一键还原成已保存的画像。
> - **当前步骤保留** —— 不再每次弹回第 1 步。
> - 未保存的内容**按公司分别存**：A 公司改了一半、去 B 公司填了点东西，切回 A 仍能看到 A 那次未保存的修改。
> - 右侧能力向量 / 推荐赛道始终按**已保存的画像**展示 —— 草稿还没落库，不代表对外生效的数据。

#### 分步填写

分 4 步填写，每步可「上一步 / 下一步」：

1. **基本信息**：公司名称（必填）、行业、成立时间、规模
2. **技术栈**：标签输入（回车添加）、核心技术描述；可上传**纯文本**公司简介自动抽取标签
3. **专利与人才**：专利标签、算法/工程/产品/销售人数
4. **资金与渠道**：融资阶段、累计融资额、渠道、客户行业

点击 **保存并重新生成** 后：

- 生成 **1536 维能力向量**
- 右侧更新 **能力雷达图**（技术/人才/资金/渠道/客户，1–5 分）
- 生成 **推荐赛道边界**（基于能力向量与赛道描述的余弦相似度，取 Top-3）

> 说明：PDF / Word 二进制文件暂不支持直接解析，请粘贴文本或手工填写。
> 各步骤内容会随步骤切换隐藏（同一时刻只显示当前步骤），这是分步表单的预期行为；
> 想确认某一步已填的内容，点顶部 **Steps 步骤条** 或「上一步」即可回到该步。

### P04 趋势雷达

- 顶部筛选：行业下拉 + 全部/顺风/逆风 切换。
- 每张趋势卡显示：置信度、评分、证据条数、方向标记。
- **查看详情**：右侧抽屉展开完整证据链与评分因子（signal_count / growth_rate / policy_support / capital_heat）。
- **加入机会池**：弹窗确认标题与说明，确认后自动生成机会卡片并跳转到赛道评分页。
- **订阅预警**：该趋势相关信号变化时会出现在监控预警列表。

趋势评分算法（技术文档 §4.2）：

```
0.3 × 信号量 + 0.3 × 增速 + 0.2 × 政策支持 + 0.2 × 资本热度
```

### P05 机会图谱

右上角三视图切换：

| 视图 | 内容 |
| --- | --- |
| 赛道地图 | ECharts 力导向图，节点按类型着色（赛道/技术/公司/机会/信号/专利/政策/融资/人才） |
| 空白点 | 用图算法找连接度低的赛道节点（degree < 5），可直接「转为机会」 |
| 中心性 | 度中心性排名 + 社区发现分簇，识别关键卡位点 |

图谱支持缩放、拖拽、节点高亮。节点超过 120 个时自动隐藏细粒度 Signal 节点以保证流畅度。

### P06 需求探针

1. 输入**关键词**（回车添加，如「质检」「漏检」「部署成本」）
2. 选择**数据源** —— 选项分两组，括号内是信号库里的**实际存量**：
   - **需求侧信号（用户发声，主证据）**：社媒 / 论坛 / 应用评论 / 招标 / 招聘
   - **补充信号（同样承载需求信息）**：产业媒体 / 论文 / 政策，以及库里现有的其余类型
3. 可选**行业**过滤
4. 点击 **开始分析**，进度条显示「检索 → 聚类 → 计算强度」三阶段

> **默认数据源** = 需求侧五类 ∪ 信号库中真实存在的类型。
> 之所以要「扩」：需求侧五类常常一条数据都没有（实测库里 48 条全是产业媒体/论文/政策），
> 只按设计口径给默认值，任何关键词都会命中 0 条 —— 页面看起来永远是空的。
> 手动改过数据源后，系统不再覆盖你的选择。

结果区：

- **痛点聚类卡片**：频次、情感、付费意愿、紧迫度、需求强度，可展开样本评论
- **综合需求强度**（1–5 分）与匹配信号数
- **样本覆盖**：负面占比、付费信号占比、紧迫度占比
- **建议验证实验**：点击任一实验将跳转到验证实验页并**自动预填假设**

**结果会跨页面保留**：切到别的菜单再回来，关键词、数据源、行业与上一次结果都还在，
顶部会标明 `上次分析 时间（关键词 … · 数据源 N 个 · 行业 …）`；
改了条件但没重跑时会提示「检索条件已改动」；点「清除结果」可回到初始空态。

需求强度算法（技术文档 §4.4）：

```
0.3 × 频次 + 0.3 × 负面情感占比 + 0.2 × 付费意愿 + 0.2 × 紧迫度
```

**口径说明（2026-09-16 放宽）**：需求强度不再只统计「用户直接发声」，
政策（强制性要求 / 补贴导向）、论文（未解的技术痛点）、产业媒体（行业诉求与扩产意图）
同样计入，因为设计口径下需求侧信号长期为零、功能实际不可用。
取数时**需求侧优先**排序，prompt 里也会如实标注证据类型，让模型自行判断可信度。
两侧证据强度并不等同：需求侧有直接的付费意愿与负面情绪表达，补充信号只体现意向。

### P07 赛道评分

- 右上角**选择机会卡片**（下拉显示标题与当前分数）。
- 若该机会尚未分析，会出现「立即分析」引导，点击 **重跑七 Agent 分析** 执行完整流水线。
- **维度表**：7 个维度（市场空间/需求真实性/技术成熟度/竞争壁垒/商业模式/时机/内部匹配度），显示权重、得分、证据数、评分理由（悬停查看完整理由）。
- **结论冲突点**：黄色告警块显示需人工裁决的矛盾（如「需求旺盛但壁垒薄弱，需警惕大厂复制风险」）。
- **配置权重**：滑块调整各维度权重，下方实时显示合计百分比（必须 100%），可点「预览排序影响」在不保存的情况下查看新评分。
- **排序对比**：所有机会按分数降序的条形图，点击可切换查看。
- 右侧：**雷达图**、**风险预警**（低于阈值的维度）、**当前评分卡**版本。

> **离开页面再回来会恢复现场**（2026-09-16 起）：
> - **选中的机会卡片保留** —— 从左侧菜单点回来，不再是「尚未选择机会」，
>   仍是你上次看的那张（连带「执行明细 / 本次分析依据」一起回来）。
> - **权重草稿保留** —— 弹窗里用滑块调过的权重不会丢，再打开弹窗还接着上次的值；
>   「预览排序影响」算出的预览分也一并保留。
> - **弹窗不会自动弹出** —— 保留的是草稿，不是打扰。
> - 草稿与预览**按机会卡片分别存**：换一张卡片看到的是那张自己的草稿，不会串。
> - 点「保存并重算排序」后草稿即作废（已落库），不会残留成「改过但没保存」的假象。

### P08 验证实验

- 右上角 **新建实验**：选择方法（6 种）、关联机会卡片（用于回写）、填写核心假设。
- 列表按状态分组：全部/进行中/已完成/草稿，支持搜索。
- 点击实验卡片进入**详情**：
  - 指标看板：每项指标的当前值 vs 目标值 + 达成率进度条
  - **状态流转**：按状态机允许的转换显示按钮（draft → running → completed → archived，running 可分支 cancelled）
  - **回写赛道评分**：把实验达成率折算到「需求真实性」维度并更新机会状态
  - **导出数据**：下载 CSV（带 BOM，Excel 直接打开不乱码）

### P09 决策报告

1. 选择机会卡片（仅显示已完成分析的）、模板、格式
2. 点击 **生成报告**

三种模板：

| 模板 | 适用 |
| --- | --- |
| 投资备忘录 | 面向投资决策委员会，强调回报、风险与退出路径 |
| 立项报告 | 面向公司管理层，强调可行性、资源与里程碑 |
| 趋势简报 | 面向战略部周会，短平快，突出信号与判断 |

报告固定 9 段结构：执行摘要 → 赛道定义与市场空间 → 需求验证 → 技术评估 → 竞争格局 → 商业模式 → 风险与应对 → 里程碑与资源需求 → 证据链附录。

**怎么看报告**（左侧「报告列表」每条有三个动作）：

| 动作 | 说明 |
| --- | --- |
| **查看全文** | 在右侧内嵌阅读，按 9 段渲染（表格、要点、证据编号都在）——**历史报告同样能看** |
| **在线打开** | 新标签页打开排版版（HTML）。若该报告还没导出过 HTML，会先自动导出一份再打开 |
| **导出 ▾** | 导出 HTML / Markdown / PPT / Word / JSON；导 HTML 会顺手在新标签页打开 |

> 报告正文存在库里（`content.sections`），列表接口只回元信息 ——
> 所以「查看全文」是**单独拉一次正文**，点开时有短暂 loading 属正常。

右侧预览区支持**导出 PPT / Word**（需后端安装 `python-pptx` / `python-docx`，未安装时自动降级为 Markdown）。

### P10 监控复盘

三个 Tab：

1. **预警列表**：按未处理/已处理/已忽略分组。每条预警显示级别、规则名、影响赛道、处置建议，可「标记已处理 / 忽略 / 复盘」。
2. **复盘看板**：记录决策依据、实际结果、复盘结论，自动生成校准建议，可一键「应用校准」。填写表单可直接记录一次复盘。
3. **模型校准**：展示校准建议表（维度 / 权重变化 / 理由）、当前评分卡与校准后的对比、历史版本对比（V1.0 → V1.1 的权重变化）。

**预警规则**（技术文档 §4.8）：大厂入场（融资金额 ≥ 1 亿且为头部主体）、政策利好、技术突破、需求激增、招标放量、监管收紧。

## 四、常见问题

**Q1：页面提示「无法连接后端服务」**
确认后端已在 8020 端口运行：`curl http://127.0.0.1:8020/api/v1/health`。
若 8020 被占用，改用其他端口启动，并同步修改 `frontend/vite.config.ts` 的 proxy target。

**Q1-2：打开 http://127.0.0.1:8020/ 看到 JSON 而不是界面**
说明前端未构建。执行 `scripts\build-frontend.cmd`（或 `cd frontend && npm run build`）后重启后端。
若只想跑 API，可忽略；若想用开发模式，设置 `SERVE_FRONTEND=false` 后另起 `npm run dev`。

**Q1-3：浏览器控制台报 `Failed to load resource: 404`**
已定位并修复（根因是 `/favicon.ico` 未提供）。若仍见 404，请执行
`python scripts/check_api_contract.py` 交叉核对前后端路径，会直接列出不匹配项。
执行前端构建后请**硬刷新**（Ctrl+F5）以清除旧缓存。

**Q8：为什么后端重启后检索变慢**
内存向量库不持久，首次分析会自动重建索引。切 pgvector / Milvus 后不再有此现象。
（若 `RAG_BACKEND=ragflow`，重启后首次检索会重新读取本地映射表，不重建 RAGFlow 索引。）

**Q9：RAG 用的是自建检索还是 RAGFlow？**

由 `backend/.env` 的 `RAG_BACKEND` 决定，默认 **`ragflow`**（全量替换）：

| 值 | 行为 |
| --- | --- |
| `ragflow` | 走外部 RAGFlow 服务（真语义嵌入 bge-m3、文档级切块）。**未配置 API Key 或服务不可达时自动降级为 `memory` 并打告警**，链路不会中断 |
| `memory` | 自建：进程内向量 + BM25 + RRF（零依赖、亚毫秒、结果确定可复现） |

**怎么判断当前实际走的是哪个？** 二选一：

- 看后端启动/首次检索日志：出现 `RAG 后端 = ragflow @ …` 即已切换；出现
  `RAGFlow 未就绪（…），降级为自建 memory 检索` 即仍在自建模式。
- 跑自查脚本：`python scripts/check_ragflow.py --list-datasets`（需 API Key）。

**当前实际状态（2026-09-14 16:09）**：✅ **已激活 RAGFlow**
—— dataset `trackcompass-signals`，40 篇文档解析完成，嵌入 `bge-m3:latest@Ollama`，
检索向量分 0.57–0.72（原自建哈希嵌入仅 0.15–0.29），单次检索 ≈162 ms。

**怎么启用 RAGFlow？** 三步（API Key 在 RAGFlow UI `http://localhost:8060` → 右上角头像 → API）：

```bash
python scripts/check_ragflow.py --api-key <KEY> --list-datasets
python scripts/check_ragflow.py --api-key <KEY> --ensure-dataset trackcompass-signals
python scripts/check_ragflow.py --api-key <KEY> --dataset-id <上一步 id> --smoke
```

把 Key 与 dataset id 写入 `backend/.env` 后重启后端即生效。

> ⚠️ **不要开启 `RAGFLOW_KEYWORD_EXTRACTION`**，除非你确认该 RAGFlow 租户的**默认对话模型**
> 已登记在 `tenant_llm` 中。否则 RAGFlow 会抛
> `LookupError: Tenant Model ... type chat not found`，导致**整条检索失败**（本机实测踩过）。
> 保持默认 `false` 只走向量 + BM25，无任何对话模型依赖。

> ⚠️ 两点必知：
> 1. **切换会改变检索结果口径** —— 自建的哈希嵌入维度 1536，RAGFlow 的 bge-m3 是 1024，
>    两者向量不可比。切回 `memory` 后需 `POST /api/v1/signals/reindex` 重建索引。
> 2. **异步解析** —— 信号同步到 RAGFlow 后有一段不可检索窗口（默认最多等 90 秒），
>    新增信号不会立刻出现在检索结果里。
