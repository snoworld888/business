# 局域网访问配置说明

> **需求**：用户 2026-09-16 ——「改成局域网可访问」
> **结论**：已改。服务默认绑定 `0.0.0.0`，同网段机器用 `http://192.168.2.192:8020/` 即可打开。
> **改动面**：3 个启动脚本 + 1 个新脚本 + `vite.config.ts` + 1 处前端文案；**零业务代码改动、零数据库改动**。

---

## 一、原本为什么只有本机可访问

| 环节 | 原状 | 是否阻塞局域网 |
| --- | --- | --- |
| 服务监听 | `uvicorn --host 127.0.0.1` ⇒ 只听回环网卡 | 🔴 **是**（唯一阻塞点） |
| 前端 API 地址 | `axios baseURL: '/api/v1'`（**相对路径**） | ✅ 否 —— 天然跟随页面来源 |
| 静态资源 | 后端同端口 `mount("/")`，相对引用 | ✅ 否 |
| CORS | `DEBUG=true` 时 `allow_origins=["*"]` | ✅ 否（且同源请求本就不触发 CORS） |

**关键点**：前端从一开始就是「同源相对路径」设计，所以只要服务绑对地址，局域网就通了 ——
不需要改 API 地址、不需要加 CORS 白名单、不需要额外入口。**缺口只有一处**。

## 二、改动清单

| 文件 | 改动 | 为什么 |
| --- | --- | --- |
| `scripts/start-all.sh` | 新增 `HOST` 变量（默认 `0.0.0.0`）；`--host "$HOST"`；启动时探测并打印**局域网地址**；开放局域网时打印防火墙放行命令与关闭方法 | 一键脚本是主入口，必须默认对 |
| `scripts/start-backend.cmd` | 同上（`set HOST=0.0.0.0` + `for /f` 探测 IP + 提示） | Windows 双击启动的路径 |
| `scripts/lan_ip.py` | **新增**。打印本机对外 IP（UDP `connect` 选路，**不实际发包**、不需外网可达） | 两个启动脚本共用同一份探测逻辑，避免两处漂移 |
| `scripts/check_lan_access.py` | **新增**。本机 / 局域网**两个来源**各跑 6 项检查 | 「绑对了」≠「能用」；只测本机地址不能宣称局域网可用 |
| `frontend/vite.config.ts` | dev server `host: '0.0.0.0'`（proxy 仍指向 `127.0.0.1:8020`） | 开发模式也要能给别人看 |
| `scripts/start-frontend.cmd` | 打印局域网地址 | 同上 |
| `frontend/src/api/client.ts` | 错误文案 `http://127.0.0.1:8010` → `（默认 8020 端口）` | 顺带修：原文案**端口写错了**（8010 是本机另一个服务），会误导排查 |

**为什么保留 `HOST` 可覆盖**：开放局域网是有代价的（见 §五），必须能一行收回本机模式。

## 三、使用方式

| 需求 | 命令 |
| --- | --- |
| 局域网可访问（**默认**） | `bash scripts/start-all.sh` |
| **仅本机**可访问 | `HOST=127.0.0.1 bash scripts/start-all.sh`<br>（CMD：先 `set HOST=127.0.0.1` 再运行脚本） |

| 查本机 IP | `python scripts/lan_ip.py` |
| 自检 | `python scripts/check_lan_access.py` |
| 同网段机器打不开 | 放行入站端口（管理员执行一次）：<br>`netsh advfirewall firewall add rule name="TrackCompass 8020" dir=in action=allow protocol=TCP localport=8020` |

## 五、⚠️ 安全提示（开放局域网是有代价的）

1. **同网段任何人都能登录**：演示账号 `admin@demo.com / TrackCompass@2026` 写在 README 与手册里，
   是公开的。开放后同一内网任何设备都能拿到管理员权限。
   - 仅在**受信任内网**使用；
   - 对外演示前请先改默认密码；
   - 不需要时用 `HOST=127.0.0.1` 收回。
2. **两个来源 = 两份登录态**：`127.0.0.1:8020` 与 `192.168.2.192:8020` 是不同 origin，
   浏览器分别存 token —— 从本机地址切到局域网地址需**重新登录一次**，属正常现象。
3. **服务仍是 `DEBUG=true` / `APP_ENV=dev`**：CORS 为 `*`。生产部署需按
   《技术文档》§8.1 切换环境分层，本次未动（不属本需求范围）。

## 六、踩坑记录（两个都是「脚本对了但没生效」）

### 6.1 给 Windows 版 Python 传 Git Bash 的 `/d/...` 路径

`start-all.sh` 里 `$ROOT` 由 `pwd` 得到，是 MSYS 风格（`/d/01code/...`）。
直接传给 `python.exe` 后报：

```
can't open file 'C:\d\01code\business\trackcompass\scripts\lan_ip.py': [Errno 2] No such file or directory
```

即 `/d` 被当成「当前盘根下的 `d` 目录」。**症状很隐蔽**：`2>/dev/null || true` 把错误吞了，
表现为「局域网地址那一行没打印」，而服务本身一切正常 —— 很容易误判成「IP 探测失败」。

**修法**：用 `cygpath -w` 转成 Windows 路径（带 `command -v` 兜底，WSL/Linux 下不动）。

**通用教训**：**给原生 Windows 程序传路径时，MSYS 风格路径不可靠**；而给 `cd`（bash 内置）传
MSYS 路径没问题 —— 所以同一变量在脚本里"有时能用有时不能用"，最容易被忽略。

### 6.2 Vite dev server 首次访问返回 000

`192.168.2.192:5180/` 首次请求返回 `000`（curl 无响应），**同一个 host:port** 的
`/api/v1/health` 却返回 200 —— 一度像是「host 检查拦截了 HTML 但放过代理」。
复测（放宽超时到 30 s）后 **200（4 ms）**，再复测 3 ms。

**真相**：Vite **首次**访问会触发依赖预构建（optimize deps），期间请求会被挂住。
不是绑定问题、不是 host 白名单问题。**判据**：同一端口"一个路径 000、另一个 200"时，
优先怀疑**是否首次访问**，复测一次即可区分。
