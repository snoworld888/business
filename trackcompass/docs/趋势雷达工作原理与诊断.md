| 结论 | **雷达是「自下而上的关键词分桶」，不是「自上而下的方向发现」。关键词在信号里存在就出现，不存在就永远不出现。** |

## 一、结论先行

| 问题 | 答案 |
| --- | --- |
| 没扫出「大模型/智能体」是 bug 吗？ | **不是 bug，是设计缺口**：雷达只做「已有信号的聚合」，没有「技术方向的发现」 |
| 直接原因 | 40 条种子信号的关键词里**根本没有**「大模型」「智能体」「人工智能」 |
| 根本原因 | 分桶以 `signals.keywords` **为唯一依据**，关键词不存在 → 桶不存在 → 趋势不存在 |
| 深层原因 | 技术文档 §4.2 要求的「采集 → NER 抽取 → 写库」链路**只实现了最后一步的分析**，缺前两步 |
| 已验证 | 注入 3 条含该关键词的信号后，两者**立即出现**为趋势（评分 0.5138、置信度 0.68、3 条证据） |

> **一句话：趋势雷达是一面"镜子"，照出的是信号库里已有的东西。
> 信号库没有的，它不会自己想到。**

> ✅ **2026-09-14 更新**：已完成三项修复 —— ① 词表补入「智能体」等前沿词；
> ② 信号入库自动抽关键词（接线 NER）；③ **能力画像接入雷达**。
> 现在画像里填了但外部无信号的能力词会以「**情报空白**」形式显式列出（不伪造为趋势）。
> 详见 §五。

## 二、工作原理（4 步）

源码：`backend/app/agents/trend.py` → `TrendReconAgent`

### 步骤 1：取信号（时间窗过滤）

```python
signals = state.since(days)      # 按 published_at 过滤窗口
```

### 步骤 2：分桶 —— **这是全流程的关键**

```python
def _bucket(self, state):
    buckets = defaultdict(list)
    for sig in state.since():
        keys = sig.keywords or []
        if not keys:
            buckets[sig.industry or "综合"].append(sig)   # 无关键词 → 退化按行业分桶
            continue
        for k in keys:
            buckets[k].append(sig)                        # ← 关键词直接当桶名
    return {k: v for k, v in buckets.items() if len(v) >= 1}
```

**桶名 = 信号自带的 `keywords` 字段原样。** 没有任何"技术方向推断"。

### 步骤 3：每个桶打分（技术文档 §4.2 原文公式）

```python
policy_support = min(1.0, len(policy_sigs) * 0.18 + hit_any(policy_text, POLICY_BOOST) * 0.05)
capital_heat   = Σ funding_sigs.metrics["amount"]
scored = trend_score(len(sigs), growth_rate(sigs), policy_support, capital_heat)
```

```
评分 = 0.3 × normalize(信号量) + 0.3 × normalize(增速) + 0.2 × 政策支持 + 0.2 × normalize(资本热度)
```

其中：
- **增速** = 近半窗信号数 vs 远半窗（`growth_rate()`）
- **政策支持** = 政策类信号条数 × 0.18 + 政策词命中数 × 0.05（上限 1.0）
- **资本热度** = 融资类信号 `metrics.amount` 求和
- **逆风惩罚**：若命中 `限制/收紧/退坡/产能过剩/泡沫/监管/降温` 超过半数 → 评分 × 0.7

### 步骤 4：产出

```python
{
  "name": 桶名,                    # ← 直接就是关键词
  "confidence": min(0.95, 0.35 + score*0.65),
  "direction": "tailwind" if score >= 0.5 else "headwind",
  "score": ..., "factors": {...},   # 可解释的四个因子
  "evidence": [Top-4 信号],
  "keywords": sorted({所有信号的 keywords 并集})[:8],
}
```

排序取 Top 10 落库到 `trends` 表。

### 数据流全貌

```
signals 表（40 条种子）
   │  keywords 字段  ← 关键：这是人工在 RAW_SIGNALS 里写死的
   ▼
_bucket()  按 keywords 分桶
   ▼
trend_score() 四因子打分
   ▼
trends 表（当前 8 条）
```

## 三、为什么没扫出「大模型」「智能体」

### 层 1（直接原因）：信号池里没有这些关键词

实测 40 条种子信号用到的**全部 18 个关键词**：

| 关键词 | 出现次数 | | 关键词 | 出现次数 |
| --- | --- | --- | --- | --- |
| 智能质检 | 13 | | 储能 | 4 |
| 计算机视觉 | 9 | | 固态电池 | 4 |
| 机器人 | 7 | | 传感器 | 3 |
| 深度学习 | 7 | | 智能排产 | 3 |
| 具身智能 | 6 | | 数字孪生 | 3 |
| 医疗器械 | 6 | | 新材料 | 3 |
| 工业互联网 | 5 | | AI+制造 | 2 |
| 预测性维护 | 4 | | 大数据 | 1 |
| 机器学习 | 4 | | 边缘计算 | 1 |

**没有「大模型」「智能体」「人工智能」中的任何一个。** 雷达自然扫不出来。

### 层 2（根本原因）：机制只做聚类，不做发现

对比《设计文档》§7.2 的要求与当前实现：

| 文档要求 | 当前实现 | 差距 |
| --- | --- | --- |
| 扫描 **PESTEL 宏观环境** | 仅按 `signals.industry` 过滤 | ❌ 无 PESTEL 维度建模 |
| 扫描 **技术成熟度曲线** | 无 | ❌ 未实现 |
| 扫描 **资本热度** | ✅ `metrics.amount` 求和 | ✅ 已实现 |
| 扫描 **政策文件** | ✅ 政策信号计数 + 词命中 | ✅ 已实现 |
| 输出**候选技术方向** | 输出 `keywords` 桶名 | ⚠️ **输出的是"标签"不是"推断出的方向"** |

> 文档要的是**自上而下的方向发现**（"从这个信号里，我判断未来 6-12 个月会爆发什么技术"）。
> 当前实现是**自下而上的信号聚类**（"已有信号里哪些标签出现得多"）。
> 这是**能力层级的差异**，不是参数问题。

### 层 3（数据管道原因）：缺了「采集」和「NER 抽取」

技术文档 §4.2 的完整流程：

```
Airflow 定时采集 → 爬虫抓政策/论文/专利/融资/新闻 → Kafka → 清洗
   → NER 抽取实体 → 写 PostgreSQL/Neo4j/Milvus → 趋势侦察 Agent 分析
```

当前实际实现情况：

| 环节 | 状态 | 证据 |
| --- | --- | --- |
| Airflow 定时采集 | ❌ 未做（属 P2-1） | 无 scheduler 代码 |
| 爬虫 / API 采集 | ❌ 未做 | 只有 40 条**手写**种子数据 `RAW_SIGNALS` |
| Kafka / 清洗 | ❌ 未做（单机不需要） | — |
| **NER 抽取实体** | ⚠️ **函数已实现，但未接线到信号入库路径** | `extract_tech_keywords()` 仅被 `api/v1/profile.py:129`（能力画像文档解析）调用；`signals` 入库路径未使用 |
| 写库 | ✅ | `POST /signals` |
| 趋势分析 | ✅ | `TrendReconAgent` |

**关键发现**：`keywords` 字段**完全依赖人工在种子数据里写死**，
信号入库时（`POST /signals`）不会自动抽取关键词。
所以只要采集层没接、NER 没接线，雷达的视野上限就＝人工关键词表的覆盖面。

### 层 4（次级问题）：词表本身也缺词

即使把 NER 接线，`TECH_VOCAB`（28 条）也缺以下技术词：

| 词 | 在词表内？ |
| --- | --- |
| 大模型 | ✅ |
| 人工智能 | ✅ |
| **智能体** | ❌ |
| **LLM** | ❌ |
| **RAG** | ❌ |
| **AI Agent** | ❌ |
| **多智能体** | ❌ |
| **MoE** | ❌ |
| **微调** | ❌ |

## 四、实证：注入即出现（机制证明）

**实验设计**：不改任何代码，只往信号池注入 3 条含目标关键词的信号，看趋势是否出现。

```
=== 扫描前：现有趋势（8 条）===
['智能质检', '计算机视觉', '工业互联网', '智能排产',
 '数字孪生', '预测性维护', '机器学习', '深度学习']
含「大模型」? False   含「智能体」? False

=== 注入 3 条含关键词 ["大模型","智能体"] 的信号 ===
  · 政策：关于推进大模型与智能体产业化的指导意见
  · 融资：某智能体平台公司完成 5 亿元 A 轮融资
  · 论文：面向企业决策的多智能体协同新架构

=== 重新索引 + 扫描 ===
扫描 23 条信号 → 生成 10 条趋势

=== 扫描后：趋势列表（10 条）===
['智能质检', '计算机视觉', '工业互联网', **'大模型'**, **'智能体'**,
 '智能排产', '数字孪生', '预测性维护', '机器学习', '深度学习']
含「大模型」? True   含「智能体」? True
  → 大模型: 评分=0.5138  置信度=0.68  方向=tailwind  证据=3 条
  → 智能体: 评分=0.5138  置信度=0.68  方向=tailwind  证据=3 条
```

**结论**：`keywords` 有 → 趋势出现；`keywords` 无 → 趋势永不出现。
**证实了雷达是「关键词驱动的映射」，不含"技术方向推断"能力。**

> 实验数据已清理，信号数回到 40、趋势数回到 8，产品数据未被改变。

## 五、修复建议（按优先级）

> ⚠️ 以下 P0 两项已于 2026-09-14 落地，并**追加了「能力画像接入雷达」** —— 见 §五之二。

### 五之一、已完成（2026-09-14）

| # | 措施 | 状态 |
| --- | --- | --- |
| P0-1 | `TECH_VOCAB` 补充「智能体 / 大语言模型 / 强化学习 / 多模态 / 知识图谱 / 算力」等 18 个前沿词 | ✅ |
| P0-2 | `POST /signals` 入库时自动抽取关键词并入 `keywords`（技术文档 §4.2 的「采集 → NER → 写库」） | ✅ |
| P0-3 | **能力画像接入雷达**（见下） | ✅ |

### 五之二、能力画像 × 外部信号（用户反馈驱动的改进）

**问题**（用户反馈）：画像里填了「智能体」「大模型」，但趋势雷达里什么都看不到，
让人以为系统漏读了填写内容。

**核查结论 —— 这其实是三个独立缺口**

| # | 缺口 | 证据 |
| --- | --- | --- |
| 1 | **雷达完全不读画像** | `trend.py` 对 `profile` **零引用**；雷达只按 `signals.keywords` 分桶 |
| 2 | **信号里根本没有这个词** | 40 条种子信号中含「智能体」**0 条**、含「大模型」**0 条** |
| 3 | 词表缺词（已修） | `TECH_VOCAB` 原本没有「智能体」 |

⇒ 即使修好词表与 NER 接线，**只要信号里没有「智能体」，雷达就永远扫不出来**。

**设计取舍：画像只做「标注」，绝不伪造趋势**

把画像里的词直接当成趋势输出是**循环论证**（用你填的东西冒充外部世界）。
所以实现上分两部分：

| 输出 | 含义 |
| --- | --- |
| `trends[].capability_match` / `matched_capabilities` | 该趋势是否命中你的能力词（有外部信号支撑） |
| **`capability_gaps`** | 画像提到、但**外部零证据**的能力词 —— **情报空白，不是趋势** |

`capability_gaps` 才是「智能体」的正确归宿：它诚实地说明
「这是你自报的能力，外部世界暂时没有对应信号 —— 要么补数据源，要么做定向调研」。

**能力词怎么取**（`capability_terms()`）

| 来源 | 处理 |
| --- | --- |
| `tech_stack`（短词，如「智能体」） | 直接采用 |
| `patents`（多为长标题） | 用 `extract_tech_keywords` 抽词，否则整句标题永远比不中 |

**自洽性约束**（已加测试锁定）：同一能力**不能**既匹配某趋势、又出现在缺口里。
实测踩过这个矛盾：`_capability_gaps()` 原先只看信号关键词，不看模型输出上的匹配结果，
导致「大模型」同时出现在两处。现在缺口在 `postprocess` 里用**最终匹配结果**重算。

**前端**：趋势页新增「能力画像 × 外部信号」面板（扫描后出现），
上排「已匹配」、下排「情报空白」，并标注后者不可作为决策依据。

---

### 五之三、原始修复建议（按优先级，保留供对照）

| 优先级 | 措施 | 说明 | 成本 |
| --- | --- | --- | --- |
| **P0** | **信号入库时自动抽关键词** | 把 `extract_tech_keywords()` 接到 `POST /signals` 与采集器回传路径：`keywords = keywords or extract_tech_keywords(title + content)` | 低（函数已存在，只需接线） |
| **P0** | **扩充 `TECH_VOCAB`** | 补入 `智能体 / LLM / RAG / AI Agent / 多智能体 / MoE / 微调 / 向量数据库 / 知识图谱` 等 | 低 |
| **P1** | **种子数据补充前沿技术信号** | 让演示数据覆盖大模型、智能体、RAG 等方向，雷达才能体现"技术面扫描"的价值 | 低 |
| **P1** | **让 LLM 真正参与方向推断** | `build_prompt()` 已就绪。切真实大模型后，Agent 能从信号**文本**里推断出"这些信号共同指向 XX 方向"，而不只是回显标签 | 中（配 `.env` 即可） |
| **P2** | **接入真实采集器** | 技术文档 §3.1 的 6 类数据源（政策/专利/融资/招聘/社媒/招标），属 P2-1 | 高 |
| **P2** | **实现 PESTEL / 技术成熟度曲线维度** | 补齐《设计文档》§7.2 要求的宏观扫描能力 | 高 |

### 为什么 P0-1「接线」最关键

当前架构下，**信号入库不抽关键词 = 雷达的输入质量完全依赖人工**。
把这一处接上，雷达立刻从"人工标签聚合"升级为"文本自动抽取聚合"，
是**投入产出比最高的一处修复**。
