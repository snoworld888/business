# 趋势能力画像链路修复报告

> 起因（用户 2026-09-16）：**「趋势雷达的逻辑我还是不清楚，会使用公司的标签、专利这些吗？现在的分析看不到这些内容。」**
> 处理指令：**「A、C 开始做，B 专利有的至少要分析趋势，要专利抽词。」**
> 全部结论基于源码逐行核对 + 运行实测。

---

## 一、先回答「逻辑」：两条独立链路，只在最后一步相交

```
外部信号（公共层）                     公司能力画像（租户私有）
      ↓                                      ↓
按 keywords 分桶 + 4 因子评分           tech_stack / patents → 能力词
      ↓                                      ↓
趋势 + 客观标签 factors._tags  ──交集──→  ⚑ 能力匹配标注
                                 ──差集──→  情报空白
```

**各环节的实际取数**（`app/agents/trend.py`）：

| 环节 | 用 `tech_stack` | 用 `patents` | 依据 |
| --- | --- | --- | --- |
| 生成趋势（分桶） | ❌ | ❌ | `_bucket()` 只用 `sig.keywords` |
| 趋势打分（4 因子） | ❌ | ❌ | `trend_score(信号数, 增长率, 政策, 资本)` |
| 趋势命名 / 描述 | ❌ | ❌ | `_describe()` 只统计信号 |
| **⚑ 能力匹配** | ✅ | ✅（修复后） | `capability_terms()` |
| **情报空白** | ✅ | ✅（修复后） | `_capability_gaps()` |

> 一句话：**外部信号决定「有哪些趋势」，公司画像只决定「怎么读这些趋势」。**
> 所以「雷达里有没有智能体」跟你的标签无关 —— 只取决于外部信号里有没有这个词。

## 二、修复项 A：分析路径漏传 `patents`（口径不一致）

### 缺陷

同一个概念有**两个入口**，传的字段不同：

| 入口 | 传给 Agent 的画像 | 含专利 |
| --- | --- | --- |
| 接口层 `deps.current_capability_terms()` | `{"tech_stack", "patents"}` | ✅ |
| **Agent 分析** `analysis.build_profile_input()` | `{"tech_stack"}` | ❌ |

而 `capability_terms()` 明确遍历 `("tech_stack", "patents")` —— **唯一的产线调用方根本不传 `patents`**。

### 后果

- `/opportunities/{id}/analyze`（七 Agent）与 `/trends/scan` 的能力词**恒不含专利**
- 趋势列表的 ⚑ 是**读取时重算**（含专利）⇒ **同一个 ⚑ 在两个页面口径不同**，可能互相矛盾

### 修复

`build_profile_input` 增加 `"patents": profile.patents or []`（`analysis.py`）。

## 三、修复项 B：专利抽词（此前专利**实际贡献恒为 0**）

### 缺陷实测

| 专利标题 | `TECH_VOCAB` 命中 | 原实现产出 | 效果 |
| --- | --- | --- | --- |
| 基于深度学习的表面缺陷检测方法 | `['深度学习']` | 与技术栈重复 | **零增量** |
| 小样本工业缺陷识别模型训练方法 | **`[]`** | **整句当能力词** | 全库 36 个标签**命中 0** |

根因：`capability_terms` 对长文本走 `extract_tech_keywords(text) or [text]` ——
词表抽不到就退回**整句**，而 15 字的句子与任何短标签都配不上。

### 新增 `base.extract_patent_terms()`

按中文技术名词的**构词法**抽，不用分词、0 新增依赖：

| 规则 | 说明 | 例 |
| --- | --- | --- |
| ① 词表命中 | 复用 `TECH_VOCAB`，术语最稳定 | 「深度学习」 |
| ② 技术对象 + 动作后缀 | 后缀表 26 个（识别/检测/训练/调度/优化…） | 工业缺陷 + 识别 |
| ③ 去套话后的短核心 | 剥离「一种/基于/面向/方法/系统/装置…」 | 「多目标优化」 |

**两个关键约束**（都是实测踩出来的）：

1. **前缀不得跨过上一个后缀** —— 否则「工业缺陷识别模型训练」会抽出
   `识别模型训练`（把前一个词吃进来）
2. **首字为词尾字则回退到 2 字** —— 否则「视觉引导机器人抓取定位」会抽出
   `器人抓取定位`（跨词残片）

### 效果（实测）

| 专利标题 | 抽出 |
| --- | --- |
| 基于深度学习的表面缺陷检测方法 | `['深度学习', '表面缺陷检测']` |
| 小样本工业缺陷识别模型训练方法 | `['工业缺陷识别', '模型训练']` |
| 一种面向多设备协同的工厂物流调度系统 | `['多设备协同', '工厂物流调度']` |
| 多目标优化与动态调度方法 | `['多目标优化', '动态调度']` |
| 面向工业场景的视觉引导机器人抓取定位方法 | `['机器人', '抓取定位']` |
| 一种大模型推理优化方法、装置及存储介质 | `['大模型', '推理优化', '大模型推理']` |

**并且不丢弃**：抽不到时仍退回原文，保证专利在「分析依据」里可见（用户要求
「专利**有的**至少要分析趋势」）。

## 四、修复项 C：`/analyze` 返回 `profile_used`（让「标注」可核查）

### 新增返回字段

```jsonc
"profile_used": {
  "company": "智造未来科技",
  "terms": ["计算机视觉", "深度学习", "边缘计算", "表面缺陷检测", "工业缺陷识别", "模型训练"],
  "by_source": [
    {"field": "tech_stack", "raw": "计算机视觉", "terms": ["计算机视觉"]},
    {"field": "patents", "raw": "小样本工业缺陷识别模型训练方法",
     "terms": ["工业缺陷识别", "模型训练"]}          // ← 能回答"这个词哪来的"
  ],
  "matched": [{"term": "计算机视觉", "trends": ["AI驱动的精密光学检测与良率优化"]}]
}
```

### 前端

`Scorecard.tsx` 新增卡片 **「本次分析依据（公司能力如何参与）」**：

- 表：`来源（技术栈/专利） | 画像条目 | 抽出的能力词`，**命中的词标金色**
- 下方逐条列出「能力词 → 命中的趋势」
- 没有命中时明确提示：这些词会出现在趋势雷达的「情报空白」区

> 这样就能直接回答「标签/专利到底用没用上、用在哪」。

## 五、连带发现（**未修，待裁决**）

### 5.1 信号关键词是**旧规则的落库快照**

发现"趋势标签里混着 `CEO`/`CTO`/`GDP`/`CVC`"后追查：这些词**当前规则已不再抽取**，
是**入库时用旧规则算好并冻结**的（与之前 `_capability` 快照、图表幂等问题同一模式）。

**已执行**数据对齐（备份 `db_backup/2026-09-16_patent-terms/`）：

```
信号关键词：11 条重算（3 条内容有变）
  移除: CEO ×2 / CTO / Pre-A / IPO      补入: HDI / KLA / PCB / iOS
趋势标签  ：4 条趋势变化，去重后 36 → 40，移除 CEO/CTO/Pre-A
```

### 5.2 ⚠️ ASCII 技术词噪声（**新增遗留 L-14**）

对齐后**仍有大量非技术词**留在标签池里。当前规则对英文词的判定是
「全大写 2–10 字」或「≥2 个大写字母」，对**新闻正文**过于宽松。实测产出：

| 类别 | 实例 |
| --- | --- |
| 财务/宏观 | `GDP` `CVC` `ROI` `DTC` `FDA` `ITNs` `TOP3` `MW` |
| 消费电子/游戏 | `PS5` `RPG` `HomePod` `iOS` `MSI` `GTX` `RTX` `i5-9400F` `i7-12700K` `OTG` |
| 人名/机构/型号 | `Wen-Hua` `KLA` `EcstaticDentist` `YANLAB` `CaSee` `HYROX` `COFE+` `KB22` `ZL202323130369.8` |
| 无意义缩写 | `FH` `FM` `FMX` `GB` `DJ` `XT` `ZB` `TPT` `ABS` `IFA` `MUSE` `SK` `PAP` |
| ✅ 真技术词 | `OpenCV` `CUDA` `CNN` `YOLOv9` `IoT` `AIoT` `CMOS` `CCD` `ADC` `DAC` `GPU` `PCB` `HDI` `SaaS` `6G` |

**噪声占比约 2/3** —— 直接污染趋势标签，进而影响能力匹配的准确性。

两条可选路线（**需你裁决**）：

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| **① 扩充停用词表** | 把实测噪声补进 `_ASCII_STOPWORDS` | 改动最小、风险低；但是"打地鼠"，新噪声还会漏进来 |
| **② 改为白名单制** | ASCII 词**只在 `EN_TECH_VOCAB` 命中、或含数字型号（`YOLOv9`/`Qwen3.8-27B`/`6G`）时**才收 | 治本、可解释；但会漏掉词表外的新技术词，需持续维护词表 |

**建议 ②**（白名单制）：本项目是垂直领域（4 个赛道），词表可控；
"漏掉一个新技术词"比"标签池里 2/3 是噪声"代价小得多。已登记为 **L-14**。
