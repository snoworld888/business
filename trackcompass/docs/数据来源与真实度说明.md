## 五、关键澄清：RAG 在链路中的真实位置

**问题**：趋势页（`/trends`）的内容是从 RAG 里提取的吗？

**答案：不是。** 趋势页与 RAG 之间**没有数据依赖**。

### 5.1 两条并行的路径

| | 路径 A —— 趋势页真正读的数据 | 路径 B —— RAG 的调用 |
| --- | --- | --- |
| 入口 | `Trends.tsx` → `GET /api/v1/trends` | `BaseAgent.run()` 第 112 行 `self.retrieve(state)` |
| 取数 | `select(Trend)` 直读 SQLite `trends` 表 | `state.rag.retrieve(query, top_k=6)` |
| 上游 | `persist_scan_result` ← trend Agent 的 `rule()` ← `_bucket(state.signals)` 按 `signals.keywords` 分桶 ← `select(Signal)` **直连 SQL** | RAG 索引（`signals` 全量灌入，`reindex()`） |
| 产出 | 趋势名 / 评分 / 四因子 / 方向 / 证据链 —— **写入 `trends` 表** | `context` 字符串 → `build_prompt` → `llm.complete` |
| 是否影响结果 | ✅ **页面内容全部由此产生** | ❌ **返回值被丢弃**（`LLM_PROVIDER=rule` 时 `rule_engine` 完全忽略 prompt） |

### 5.2 对照实验（决定性证据）

把 RAG 替换成两个内容完全不同的桩，观察趋势结果是否变化：

| 桩 | RAG 返回内容 | 趋势结果 | 证据条数 |
| --- | --- | --- | --- |
| A | **空**（模拟索引为空） | 智能质检 / 计算机视觉 / 工业互联网 / 智能排产 / 数字孪生 / 预测性维护 / 机器学习 / 深度学习 | 0 |
| B | **伪造的「量子计算突破」** | **完全相同的 8 条，一字不差** | 1 |

⇒ **趋势名、评分、排序对 RAG 内容完全不敏感。** 唯一变化的是证据条数（1 条之差）。

### 5.3 必须诚实说明的一个细节

RAG **确实被调用了** —— `BaseAgent.run()` 的 `self.retrieve(state)` 是**无条件执行**的，
而且**有副作用**：它会把 RAG 命中的文档追加进 `state.evidence`。

所以准确表述是：

> **RAG 被调用了，但它的返回值对趋势页零影响。**
> 它对**分析/决策/报告**路径（`llm.complete` 之上的链路）才可能起作用 ——
> 而当前 `LLM_PROVIDER=rule`，连那条路也是关闭的。

另外，趋势页展示的「证据链 N 条」取自 `trends.evidence` 列，
由 `rule()` 中 `top = sorted(sigs, ...)` 从 **signal 行**构造，**同样不是 RAG**。

### 5.4 当前 RAG 实况（2026-09-14 16:09 已切到 RAGFlow）

| 项 | 值 |
| --- | --- |
| `RAG_BACKEND` 配置 | `ragflow` |
| 实际生效引擎 | **`RAGFlowEngine`**（已激活，非降级） |
| dataset | `trackcompass-signals`（`19a68252b01311f18c92bfc493440fd4`） |
| 索引规模 | **40 篇文档 / 40 chunks，解析全部成功（0 失败）** |
| 嵌入后端 | **`bge-m3:latest@Ollama`（1024 维，真语义嵌入）** |
| 检索耗时 | ≈162 ms（自建 memory 时代为亚毫秒） |
| 向量分实测 | **0.57–0.72**（哈希嵌入时代仅 0.15–0.29） |

**切换后结论是否改变？** —— **没有**。用同一套换桩对照实验复验：
把 RAG 换成「返回空」与「返回伪造量子计算」两个桩，**8 条趋势的名称与评分依旧完全一致**。

> 因为 `rule()` 根本没读 `state.evidence` —— 趋势只由 `signals.keywords` 分桶决定。
> **RAG 生效改变的是「证据链能取到真语义相关的原文」，不是「趋势怎么算出来」。**

**仍然存在的一处空转**：RAG 的返回值只进入 `build_prompt` → `llm.complete`，
而当前 `LLM_PROVIDER=rule`，prompt 被忽略。
⇒ **要让 RAG 真正参与"推理"，必须同时把 `LLM_PROVIDER` 切到真实模型。**

## 八、诚实总结

**这套系统的真实能力是**：把结构化的企业能力数据，用确定性算法映射到赛道机会评分，
并给出**可追溯、可断言、可复现**的决策依据链。

**它目前不具备的能力是**：
1. 获取任何外部真实数据（全部为种子）
2. 用大模型做推理或生成（全部为规则与模板）
3. 真语义检索（当前为哈希嵌入，语义能力弱）

**这不等于它没用** —— 骨架、契约、算法、可回归性都是真的且经过验证。
但要对外宣称「AI 驱动的产业机会发现」，**P0 的两项必须先补齐**。
