# 登录「点了不跳转」+ 需求探针白屏 修复报告

> **触发**：用户 2026-09-16 ——「登录不跳转」
> **结论**：用户报的是一个缺陷；核查过程中**又挖出第二个更严重的缺陷**（需求探针整页白屏）。
> 两者都已修复。
> **改动面**：前端 4 个文件（1 新增）+ 后端 2 个文件 + 2 个脚本 + 1 新增诊断脚本；
> **零数据库改动、零 `.env` 改动、零新依赖**。

## 一、缺陷 A：登录后不跳转（用户报告）

### 现象

用真实浏览器走表单登录，修复前：

```
清空登录态后：URL = http://127.0.0.1:8020/#/login
localStorage token：null
已点击登录，开始采样 URL 时间线...
  0.4s  #/login            ← 点了登录，hash 压根没变过
最终状态：
  token: ok / user: ok     ← 登录接口成功、token 已落盘
  onLoginPage: true        ← 但仍停在登录页
```

**关键证据**：token 与 user **都已写入 localStorage**（说明接口调用成功、`login()` 跑完了），
但 URL 停在 `#/login` —— 所以不是「登录失败」，而是「进去了又被弹回来」。
**手动刷新一下就能进**，这正是最容易被当成「偶发」而放过的形态。

### 根因：认证状态存了两份，而路由守卫看的是它自己那份

`hooks/useAuth.ts` 原实现把状态放在组件内 `useState`：

| 组件 | 角色 | 状态 |
| --- | --- | --- |
| `App` | 路由守卫（`isAuthenticated ? <AppLayout> : <Navigate to="/login">`） | 自己的一份 `useState` |
| `Login` | 登录表单 | **另**一份 `useState` |

时序：

```
1. 访问 #/login       → App 渲染，token=null ⇒ isAuthenticated=false
2. Login 调 login()   → 写 localStorage + setUser（只更新 Login 那份）
3. navigate('/dashboard')
4. App **没有重渲染**（它没消费 location；React 对相同 element 引用会 bailout）
   ⇒ 它的 isAuthenticated 仍是 false
5. 外层路由匹配 path="/*" 且 isAuthenticated=false ⇒ <Navigate to="/login" replace/>
   ⇒ 被弹回登录页
```

隐蔽之处：`token = storage.getToken()` 是**渲染时读一次的普通变量**（不是 state），
只在组件重渲染时才更新 —— 而这里恰恰不会重渲染。

### 修法：认证状态改为模块级单例

新增 `frontend/src/api/authStore.ts`，与既有 `api/taskStore.ts` **同构**
（模块级快照 + `useSyncExternalStore` 订阅）：

- `getAuthSnapshot()` / `subscribeAuth()` / `setAuthSnapshot()` / `resetAuthSnapshot()`
- 快照**引用稳定**（只在真正变化时重建）—— 否则 `useSyncExternalStore` 会无限重渲染
- 存储键（`TOKEN_KEY`/`USER_KEY`）也搬到这里，让 `client.ts` 能反向调用
  `resetAuthSnapshot()` 而不产生循环依赖

`hooks/useAuth.ts`：改用 `useSyncExternalStore`；`login()` 里一次写入共享快照。
**`useAuth()` 调用签名不变，14 个调用点零改动。**

`api/client.ts`：`storage.clear()` 里补 `resetAuthSnapshot()` ——
否则 401 / 登出清了 localStorage 而内存快照仍是「已登录」，
会出现「一边跳登录页、一边被守卫判为已登录」的不一致。

### 连带修掉：登出同样不会跳转

同一根因的另一面 —— `AppLayout` 调 `logout()` 也是更新它自己那份 state，
守卫不更新 ⇒ **登出后停在原页面**（localStorage 已清空，刷新才回登录页）。共享单例后一并修复。

## 二、缺陷 B：需求探针整页白屏（核查中发现）

### 现象

改完 A 之后跑 UI 冒烟，卡在：

```
❌ 等待页面文本超时：痛点聚类
  当前 URL：http://127.0.0.1:8020/#/demand
  页面文本：            ← 空
```

**「页面文本为空」这句话本身极具误导性**：它既可能是「页面真崩了」，
也可能是「读取那一刻页面在导航」（`Runtime.evaluate` 抛错被 `.catch(() => '')` 吞掉）。
第一轮排查时它就把我引向了「接口是不是挂了」——但后端日志显示探针一直正常返回
（`POST /api/v1/demand/probe 8871.4ms` / `210.8ms` 均为 200）。

### 定位手段

写 `scripts/diag_page.mjs`（通用页面诊断：打开页面 → 采样文本 → 抓**控制台报错**与**整页导航**），
一次就拿到答案：

```
[console.error] Error: Objects are not valid as a React child
  (found: object with keys {hypothesis, target_pain_point, metric})
```

### 根因：LLM 返回结构化对象，前端当文本渲染

真实 LLM 对「建议验证实验」返回的是**结构化对象**：

```json
{"hypothesis": "针对AI手机用户，提供可视化的数据本地化处理证明…",
 "target_pain_point": "AI手机隐私与数据安全焦虑",
 "metric": "隐私功能开启率, 购买转化率, 用户信任度评分"}
```

而 `Demand.tsx` 是 `{e}` 直接渲染 + `key={e}`：

```jsx
{result.suggested_experiments.map((e) => (
  <Button key={e} block onClick={() => createExperiment(e)}>{e}</Button>
))}
```

React 遇到「对象作 child」会**抛错并卸载整棵树** ⇒ **整页白屏**（不是局部报错）。
后端 `postprocess()` 当时只归一了 `pain_points[].experiments`，
**顶层 `suggested_experiments` 被原样透传**。

> 这不是巧合：`postprocess` 里已有的注释记录过**同类**事故 ——
> 模型不输出 `p.experiments` 时前端 `undefined.map()` 也曾让整页白屏。
> **同一个模式第二次发作**：*模型输出不被约束 ⇒ 前端白屏*。

### 修法（两端都做）

**后端** —— `app/agents/base.py` 新增 `normalize_experiments()`，
把元素归一为字符串（优先取 `hypothesis`，未知结构则拼接字符串值）；
`demand.py::postprocess()` 用它收敛 `suggested_experiments`，
缺失时按规则路径「从痛点 experiments 汇总 → 兜底默认三项」。

**前端** —— `Demand.tsx` 新增 `experimentLabel(e: unknown): string` 兜底，
用于 `suggested_experiments` / `p.experiments` / `p.samples` 三处渲染与 `key`。

**为什么两端都要**：后端归一保证**新数据**结构一致；前端兜底保证
**历史缓存 / 未来漂移**也不会白屏 —— 一次白屏的代价是「整页不可用且看不出原因」，
防御成本远低于代价。

### 为什么以前没暴露

上一轮在**局域网 origin** 跑冒烟时是 46/46 全绿 —— 那次探针走了 **LLM 缓存**，
缓存里是旧格式（字符串），所以没崩。这次缓存过期走了真实推理，
拿到结构化对象，才稳定复现。⇒ **拿缓存当验证依据会漏掉真实推理的形态差异。**

## 三、为什么这两个缺陷都没被既有测试拦住

| 缺陷 | 为什么漏掉 |
| --- | --- |
| A 登录不跳转 | 冒烟原来的起手式是「接口登录 → 把 token 写进 localStorage → 整页 reload」，**绕过了登录表单**。更巧的是那次 reload 恰好绕开了缺陷（reload 后模块重新加载，从 localStorage 读到 token）⇒ 「看起来一切正常」 |
| B 整页白屏 | 单测跑 `LLM_PROVIDER=rule`（规则路径输出本来就是字符串），**真实 LLM 的形态差异只在缓存未命中时出现** |

**两条已落地的规则**：

1. **冒烟不能绕过真实入口** —— 注入状态跑得快，但会系统性地掩盖入口链路缺陷。
   本次已把 `ui_smoke_persist.mjs` 起手式改为**真实表单登录**（净增 1 条断言）。
2. **断言失败信息不能吞掉异常** —— `waitForText` 原先把 `Runtime.evaluate` 的异常
   吞成空串，导致「页面在导航」看起来像「页面白屏」。现在改为
   **不吞错 + 附带整页导航历史 + 附带控制台报错**。

## 六、结构性防护（原 D1/D2，2026-09-17 落地）

> 用户对 D1/D2 裁决「同意」后实施。**两条都是「防复发」而不是「修个案」** ——
> 接入真实 LLM 后「输出结构漂移」会反复出现，每次代价都曾是整页不可用。

### 6.1 ErrorBoundary：把「整页白屏」降级为「局部错误 + 可读原因」

新增 `frontend/src/components/ErrorBoundary.tsx`，两级接入：

| 层级 | 位置 | 作用 |
| --- | --- | --- |
| **路由级** | `App.tsx` 内包住 `<Routes>`（`RouteBoundary`） | 单页崩了只有**内容区**变成错误提示，**侧栏导航仍可用**；`key={pathname}` ⇒ 切页自动重置 |
| **顶层** | `main.tsx` 包住 `<App/>` | 连 `AppLayout` 都渲染不出来时兜底 |

三个设计要点：

1. **把 `error.message` 显示出来** —— 空白页最要命的不是崩溃，而是「什么都不知道」；
2. **给出路**：重试 / 回到工作台 / 刷新页面；
3. **额外打一条 `[ErrorBoundary]` 前缀的 console.error** —— 自动化诊断（CDP 抓 console）据此可直接定位。

**实测**（真实浏览器，临时在 `Dashboard.tsx` 注入一行 `throw` 触发）：

```
TC_HASH='#/dashboard?crash=1' node scripts/diag_page.mjs
  t+0s  len=180
      命中关键文本：这块内容渲染出错了 / 回到工作台 / 工作台 / 能力画像 / 趋势雷达 / 错误信息
      末尾：… 侧栏（工作台/能力画像/信号库/趋势雷达/…/设置）/ 这块内容渲染出错了 /
            其余功能仍可正常使用… / 重 试 / 回到工作台 / 刷新页面 / 错误信息 /
            ErrorBoundary 自检：这是故意抛出的渲染错误（验证用）
```

对照修复前：同样的错误会让 `document.body.innerText` 变成 **空串**（整页白屏，侧栏一并消失）。
截图留档：`docs/错误边界-兜底验证.png`。自检代码**验证后已移除**（`git diff` 确认 0 处残留）。

### 6.2 LLM 输出防御推广

**前端**：把 `Demand.tsx` 里的本地实现提升为共享工具 `components/widgets.tsx::safeText(e: unknown): string`
（字符串原样 → 对象按常见文本键取值 → 拼字符串值 → `String()`；**永不返回对象**），并加固到：

| 位置 | 理由 |
| --- | --- |
| `Demand.tsx` 三处（samples / p.experiments / suggested_experiments） | 本次事故现场 |
| `Scorecard.tsx` 的 `conflicts` 渲染 | 同为「若模型返回对象就白屏」的形态 |
| `widgets.tsx` 的 `MetricBar.label` / `RankingBars.item.title` / `StatCard.{label,value,suffix}` | **通用展示组件是更好的防线位置**：任何传给它们的数据都不该让它们崩 |

**后端**：把 `normalize_experiments()` 泛化为 `normalize_text_list(items, preferred_keys)`（旧名保留为语义化包装），
并在 `decision.py::postprocess()` 里归一 `conflicts`。

> ⚠️ 归一 `conflicts` 时有个**保护**：**只在归一结果非空时覆盖**。
> 模型没给该字段时若直接写空列表，会把规则基线产出的「结论冲突点（需人工裁决）」清掉 ——
> 那是业务提示，不能被抹掉。已用单测锁定（`TestConflictContract::test_missing_conflicts_not_cleared`）。

**残留风险（已用 ErrorBoundary 兜底）**：其他页面（趋势/监控/报告）仍可能有未发现的「裸渲染」点 ——
但它们现在最坏是「局部错误提示」，不再是整页白屏。
