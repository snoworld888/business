# 趋势累积语义分析 —— 近义重复还是真差异

> 分析日期 2026-09-16　｜　数据来自实测，非推断
> 复现：`python scripts/analyze_trend_similarity.py`

---

## 1. 问题

趋势落库的 upsert 键是 `(tenant_id, name)` **精确匹配**，而 LLM 每次生成的趋势名都不同
⇒ 同名才更新、异名必新增。反复扫描后「看起来像重复」的趋势越积越多
（实测 6 次扫描累积到 17 条）。

但"看起来像"是主观判断。本文用**向量相似度**给出客观依据，并回答一个更关键的问题：
**去掉共用模板词后，真正差异部分的语义差距有多大？**

---

## 2. 样本与方法

| 项 | 说明 |
| --- | --- |
| 样本 | `db_backup/2026-09-15_trend-reset` 中的 **17 条**趋势名 —— 同一批真实信号（48 条）被反复扫描 6 次所产生的全部结果 |
| 为什么用这个样本 | 「同源多次扫描」最干净：差异**只来自 LLM 措辞抖动**，不掺数据变化 |
| 向量模型 | **bge-m3**（1024 维，Ollama）。⚠️ 必须用真语义模型 —— 项目默认的 `LocalHashEmbedding` 是确定性哈希，**不携带语义**，算出的相似度毫无意义 |
| 指标 | 两两余弦相似度；另做「差异词」单算 |

### 2.1 人工标注的对照分组

按语义把 17 条归入 4 组（光学/视觉检测、具身智能、碳管理、算力/边缘），用于对照向量结果。

### 3.2 分布

| 组别 | n | min | 中位 | max | 均值 |
| --- | --- | --- | --- | --- | --- |
| 同主题组内 | 31 | 0.4253 | 0.6562 | **0.9823** | 0.6783 |
| 跨主题 | 105 | 0.4157 | 0.5002 | **0.7132** | 0.5200 |

### 3.3 ⚠️ 关键结论：单一阈值分不开

```
跨主题最高 0.7132   ←─┐
                     ├─ 区间重叠 ⇒ 无法用一条阈值切割
同主题最低 0.4253   ←─┘
```

跨主题（`工业碳管理` ⟷ `精密光学检测`）都能到 **0.7132**，而同主题也可能低到 **0.4253**
（我的粗暴关键词分组把「光子计算」和「工业视觉数据增强」划到了一组，属标注误差，
但**重叠这件事本身成立**）。

**⇒ 任何"相似度 > X 就合并"的方案都会误伤。**

## 4. 差异词分析（回答"真正差异有多大"）

趋势名有大量**共用模板词**（「AI驱动的」「具身智能在」「与」「的场景」…）。
去掉公共词后，单独比**差异片段**的语义：

| 整体相似度 | **差异词相似度** | 公共词 | 差异片段 A ⟷ B |
| --- | --- | --- | --- |
| 0.9823 | — | AI赋能工业碳管理与绿色制造 | **「的」⟷（空）** |
| 0.9168 | **0.5213** | 具身智能在垂直场景的商业化 | 闭环 ⟷ 落地 |
| 0.9129 | **0.6587** | 具身智能在垂直场景的落地 | 服务规模化 ⟷ 商业化 |
| 0.9126 | **0.4752** | AI的工业碳管理 | **驱动 ⟷ 赋能与绿色制造** |
| 0.9062 | **0.5082** | AI驱动的精密光学检测与 | 良率优化 ⟷ 质量控制 |
| 0.8971 | **0.4563** | AI工业碳管理 | **驱动的 ⟷ 赋能与绿色制造** |
| 0.8261 | **0.5466** | 具身智能在垂直场景的 | 商业化闭环 ⟷ 服务规模化落地 |
| 0.7645 | **0.6499** | 边缘算力与 | AI硬件本地化智能终端 ⟷ AIoT本地基础设施普及 |

### 4.1 第一个重要发现

**整体相似度 >0.9 的对，差异词相似度只有 0.45–0.66。**

⇒ 「整体很像」**主要是模板词贡献的**，短文本相似度被公共前缀严重抬高。
只看整体相似度会**系统性高估**重复程度。

### 4.2 第二个重要发现：差异词相似度也分不开

「驱动 ⟷ 赋能」（**同义词**，语义零差异）相似度 **0.4752**；
「良率优化 ⟷ 质量控制」（**真不同侧重**）相似度 **0.5082**。

两个值太接近 ⇒ **差异词相似度同样无法单独判别**。

---

## 5. 累积的四种情形（这是回答的核心）

把上面 8 对按**语义是否真的不同**归类，得到四种本质不同的"重复"：

| # | 情形 | 例 | 该不该合并 |
| --- | --- | --- | --- |
| ① | **纯措辞抖动** | 「…的工业碳管理」⟷「…工业碳管理」（差一个「的」） | ✅ **合并**（零语义差异） |
| ② | **同义模板词替换** | 「AI**驱动**的」⟷「AI**赋能**的」 | ✅ **合并**（驱动/赋能近义） |
| ③ | **包含关系** | 「工业碳管理」⟷「工业碳管理与绿色制造」 | ✅ **合并**（后者是前者超集，取完整者） |
| ④ | **实义侧重差异** | 「**良率优化**」⟷「**质量控制**」 | ❌ **保留**（关注点确实不同） |

**只有 ④ 是真差异。** ①②③ 都是 LLM 措辞不稳造成的伪重复。

### 5.1 关键验证：这些高相似度对的证据是**同一批信号**

对 17 条趋势两两算证据集合的 Jaccard：

| 名字相似度 | **证据 Jaccard** | 趋势 A ⟷ B |
| --- | --- | --- |
| 0.9129 | **1.000**（2/2） | 具身智能在垂直服务场景的规模化落地 ⟷ 具身智能在垂直场景的商业化落地 |
| 0.9168 | **1.000**（2/2） | 具身智能在垂直场景的商业化闭环 ⟷ 具身智能在垂直服务场景的规模化落地 |
| 0.9126 | **1.000**（2/2） | AI驱动的工业碳管理 ⟷ AI赋能工业碳管理与绿色制造 |
| 0.7645 | 0.667（2/3） | 边缘AI算力硬件与本地化智能终端 ⟷ 边缘AIoT与本地算力基础设施普及 |
| — | 0.500（1/2） | 具身智能与机器人产业资本化 ⟷ AI赋能工业碳管理与绿色制造（**跨主题**） |

**⇒ 名字相似度 0.91 的那几对，证据集合 100% 重叠** —— 它们**确实是同一次聚类的产物**，
只是被 LLM 起了不同的名字。属 §5 表中的 ①②③（伪重复），**应当合并**。

而「良率优化 ⟷ 质量控制」这类**末段不同的**，若证据同样重叠，也是伪重复。

> 这也解释了为什么「差异词相似度」判别不了（§4.2）：
> LLM 换的是**模板词**（驱动/赋能、闭环/落地），证据压根没变。

### 5.2 但小证据集合会放大噪声

上表最后一行暴露一个陷阱：两条趋势各只有 1–2 条证据，共用 1 条时
Jaccard 就冲到 **0.5**（跨主题也会）。

**⇒ 判据必须带「最小交集数」下限**，不能只看比例。

## 6. 建议方案：按「证据信号」去重，而不是按名字

以上分析说明**名字相似度不可靠**（无论整体还是差异词）。根因是：
**名字是 LLM 编的，证据是事实。**

趋势是从信号聚出来的 ⇒ **同一批信号聚出的趋势就是同一个趋势**，与它叫什么名字无关。

实测支持：`AI算力硬件高精度光学检测` 与 `AI驱动的精密光学检测与良率优化`，
证据都是同一篇 36 氪文章（「前高通算法研发经理跨界AI算力板检测，获近亿元战略投资」）
⇒ 证据集合完全重叠，按证据去重可正确识别为重复。

### 推荐方案

**去重键 = 证据信号集合的「Jaccard + 最小交集数」双条件**

```
新趋势的 evidence 集合 E_new
   ↓ 与库中同租户、同 industry 的每条趋势的 E_old 比较
|E_new ∩ E_old| ≥ 2  且  Jaccard ≥ 0.7   → 同一趋势：更新（保留更完整的名字）
否则                                      → 新增
```

实测这两条判据能**干净分开**：

| 情形 | Jaccard | 交集 | 判定 |
| --- | --- | --- | --- |
| 真重复对（名字 0.91–0.98） | 1.000 | 2 | ✅ 合并 |
| 跨主题对（各 1–2 条证据偶然共 1 条） | 0.500 | 1 | ❌ 交集不足，不合并 |

**为什么必须加「交集 ≥ 2」**：趋势的证据通常只有 1–3 条，小集合上
Jaccard 会被单条共享信号放大到 0.5 —— 只看比例必然假阳性。

**为什么比名字可靠**：名字是 LLM 编的（同一批信号可以被起 3 个不同名字），
证据是事实。实测名字相似度 0.91 的三对，证据重叠率是 **100%**。

### 辅助信号（用于消歧）

| 信号 | 用途 |
| --- | --- |
| 名字**包含关系** | A 是 B 的子串 → 取更完整的名字 |
| 模板词归一化后比较核心词 | 「AI驱动/AI赋能」归一为同一模板 |
| `industry` 是否相同 | 不同行业的趋势绝不合并 |
| 创建时间窗口 | 同一次扫描产出的才可能是同一主题 |

### 为什么不直接用聚类

用 bge-m3 对趋势名做聚类（HDBSCAN / 层次聚类）理论可行，但：
- 名字向量的**模板词噪声太大**（见 §4.1）
- 聚类**无法处理"包含关系"**（③）—— 子串关系最好用字符串判定
- 引入新依赖（sklearn/hdbscan），违背项目「零新增依赖」约定

⇒ **证据信号 Jaccard 是更简单、更可靠、零依赖的判据。**

## 7. 复现方式

```bash
# 默认：分析 trend-reset 备份（同源多次扫描样本）
python scripts/analyze_trend_similarity.py

# 换样本 / 用当前库
python scripts/analyze_trend_similarity.py --backup 2026-09-15_remove-seed
python scripts/analyze_trend_similarity.py --live

# 调整展示条数
python scripts/analyze_trend_similarity.py --top 20
```

脚本会输出：样本清单 → 相似度矩阵 Top-N → 分布统计 → 阈值参考 → **差异词对照表**。

> ⚠️ 脚本依赖 `bge-m3`（Ollama）。若 Ollama 未启动会直接报错退出，
> 不会退回哈希嵌入 —— 那会产出**看似合理但完全无意义**的相似度。
